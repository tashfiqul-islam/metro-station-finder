Foundation configuration hardening
Identity: metro-foundation-hardening. Immutable revision: 2026-11-03-r1. Decision owner: Tashfiqul Islam; explicitly requested gap ticket and implementation in this chat on 2026-11-03.
Problem: METRO-11 scaffold passes its baseline, but package/runtime pins, TypeScript strictness, configuration formatting, and runtime separation do not meet the requested foundation standard. Slice: foundation. Outcome: reproducible, strictly checked, consistently formatted configuration and a documented update policy.
Scope
Verify latest stable direct dependencies and runtimes against official sources; update exact pins and lockfile with compatibility evidence. Adopt stable TypeScript 7 with explicit compiler-API compatibility dependency if required. Strict shared options plus separate web, Worker, Node and Bun ambient boundaries. Format and validate tracked JSON, JSONC and TOML. Structure package metadata/scripts and mise tasks coherently. Add bunfig only for a concrete supported setting. Protect local secrets/generated files while tracking safe examples. Document configuration ownership and ongoing quality expectations.
Acceptance
CFG-1: Given a fresh checkout with pinned tools, when bootstrap, check, build and smoke run, then all pass; every direct dependency/runtime pin has dated official release evidence or an explicit compatibility exception.
CFG-2: Given mismatched package/mise/runtime configuration or malformed required configuration, when the configuration gate runs, then it exits nonzero with actionable diagnostics.
CFG-3: Given unsafe indexed access, invalid explicit undefined on an optional property, implicit return gaps, unused declarations, or cross-runtime ambient globals, when the appropriate TypeScript project checks the fixture, then it rejects it; valid fixtures pass. Strict options must not be weakened to silence errors.
CFG-4: Given malformed or unformatted tracked JSON/JSONC/TOML, when format/validation checks run, then they fail; canonical formatting is idempotent and check-only mode does not mutate files.
CFG-5: Given local .env/.dev.vars files and generated output, when Git ignore rules are checked, then secrets/artifacts are ignored while safe example templates and required shared configuration remain trackable.
CFG-6: Given the completed branch, when reviewed and integrated, then existing domain isolation, development lifecycle and smoke behavior remain passing; merge target remains feature/metro-rebuild and default branch is unchanged.
Testing seams
CFG-S1: actual configuration parser/guard with temporary mismatched and malformed files (CFG-1/2). CFG-S2: real TypeScript compiler and distinct runtime projects, valid and invalid fixtures (CFG-3/6). CFG-S3: actual pinned formatter CLI on JSON/JSONC/TOML fixtures and tracked files, compare bytes after check and repeated format (CFG-4). CFG-S4: git check-ignore for secret/generated/example paths (CFG-5). Full bootstrap/check/build/browser-and-HTTP smoke plus existing preparation validator and negative cases (CFG-1/6). These checks fail on base due to old pins, absent strict checks/runtime separation, missing format gate and missing secret ignore rules.
Constraints and exclusions
No product features, deployment, provider contracts, master ancestry, default-branch switch, release, broad CI/protection/hooks/lint graph rollout (METRO-12). No fallback code, weaker tests, unverified latest claims, cosmetic-only dependency or configuration files. Bun remains package manager. Signing remains enabled. Required tools: existing isolated worktree, Bun/mise, GitHub/Plane access and local browser fixtures.
Grouping: existing module 02 Repository and delivery foundation (f225309b-c896-4168-a32a-92badc4f6262). Milestone/release unassigned: foundation work does not establish shipping. Blockers: empty; METRO-11 completed. AFK implementation and review authorized; signing may require owner prompt. Readiness: bounded outcome and seams settled; exact release selection verified before edits and recorded in repository evidence. METRO-12 consumes this foundation afterward.
