## Decisions

| #   | Question                | Decision                                                                                                                                                                                                                                                                                                                                                                                             | Reason                                                                                                                                                                                                                 |
| --- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Preview model           | One Worker per pull request, named `metro-scaffold-pr-<number>`, deployed with `wrangler deploy --name … --var PREVIEW_SHA:<sha>`; deleted when the pull request closes.                                                                                                                                                                                                                             | No production Worker exists, so a version upload to `metro-scaffold` would have to create it first, which implies a cutover. A per-PR Worker is isolated, disposable and has its own version history for the rollback. |
| 2   | workers.dev             | Enabled only for preview Workers, through the `env.preview` block of `apps/api/wrangler.jsonc` (`workers_dev: true`). The default (production) config keeps `workers_dev: false`.                                                                                                                                                                                                                    | Preview needs a URL; production stays closed.                                                                                                                                                                          |
| 3   | Secrets                 | A GitHub environment `preview` holds `CLOUDFLARE_API_TOKEN` (secret) and `CLOUDFLARE_ACCOUNT_ID` (variable, an identifier and not a credential). Token scope: Workers Scripts edit for this account only. The workflow fails with an actionable message when either is missing. The current token expires 2026-12-03; rotation is the owner's. The values never enter the repository or `.dev.vars`. | Least privilege; environment scoping keeps the secrets away from non-preview jobs.                                                                                                                                     |
| 4   | Fork pull requests      | Same-repository pull requests only (`head.repo.full_name == github.repository`). Forks get no secrets and no deploy.                                                                                                                                                                                                                                                                                 | Secrets must not reach untrusted code.                                                                                                                                                                                 |
| 5   | Trigger                 | A gated `preview` job inside `.github/workflows/quality.yml`, `needs: [checks, build, security]`. It is not in the `Quality gates` aggregate, so the required check does not depend on Cloudflare availability.                                                                                                                                                                                      | A `workflow_run` workflow runs only from the default branch (`master`), so it cannot fire for the rebuild until the default-branch switch. A job in the same workflow works on every branch today.                     |
| 6   | Rollback                | `wrangler rollback` on the preview Worker to the previous version is the accepted procedure, exercised by the preview job after the smoke on every deployment that has a previous version. No production traffic is touched.                                                                                                                                                                         | Preview Workers accumulate versions across pushes.                                                                                                                                                                     |
| 7   | Request ID and logging  | Header `x-request-id` (accept a client value matching `^[A-Za-z0-9_-]{8,64}$`, else a fresh UUID), echoed on every API response. One JSON line per request: `level`, `event`, `requestId`, `method`, `path`, `status`, `durationMs`. Errors log `errorName` only.                                                                                                                                    | Correlation without leaking input.                                                                                                                                                                                     |
| 8   | Redaction               | Query strings, headers, bodies, cookies and error messages are never logged; only the path. So API keys, coordinates and tokens (which travel in those places) cannot reach a log line.                                                                                                                                                                                                              | Allow-list beats a deny-list.                                                                                                                                                                                          |
| 9   | OTLP                    | Out of scope; constraint documented: Workers Observability exports JSON logs through Cloudflare, so the log shape above is the integration contract.                                                                                                                                                                                                                                                 | Matches ticket scope ("document constraints").                                                                                                                                                                         |
| 10  | Identity of the preview | The deployed Worker serves `GET /api/scaffold/status`; the preview SHA is exposed as the `x-preview-sha` response header (from the `PREVIEW_SHA` var) so the smoke can prove the URL serves the checked commit. Absent outside previews.                                                                                                                                                             | Acceptance: "Preview contains exact checked SHA".                                                                                                                                                                      |

## Acceptance (rewritten from the ticket)

1. A preview job deploys only after `checks`, `build` and `security` succeed, only for same-repository pull requests; a failed required job leaves the preview job skipped (proved by workflow lint and a test of the job conditions).
2. After deploy, the job requests the preview URL: `/` returns 200 HTML, `/api/scaffold/status` returns the schema-valid body and `x-preview-sha` equal to the head SHA, an unknown `/api/x` returns the 404 envelope. Any mismatch fails the job.
3. Missing `CLOUDFLARE_API_TOKEN` or `CLOUDFLARE_ACCOUNT_ID` fails the job with a message naming the missing secret and the environment.
4. Every API response carries `x-request-id`; the log line has the fields above; a test proves query string, headers and error message are absent from logs.
5. The job runs `wrangler rollback` on the preview Worker and re-checks the URL; a Worker with only one version skips the rollback and says so.
6. Closing the pull request deletes its Worker.
7. No production Worker, no custom domain, no route change.

## Out of scope

Custom domains, production deployment, release automation (METRO-14), OTLP export, secrets in the repository.
