# Local workspace

**Confirmed / Repo-verified:** this independent rebuild contains a React/Vite web app, a Hono Cloudflare Worker, a dependency-free core package and a schema-validated contracts package. The Worker has one route, `POST /api/vitals` (METRO-93 retired the synthetic status route; ADR-0019 added it), and the page at `/` is the nearest-station slice. It is not product health, data correctness or Metro feature parity.

## Bootstrap and commands

Prerequisites: mise, PowerShell 7 for preparation checks, and an OS supported by the pinned Node/Bun and Wrangler local runtime. Windows execution was checked, and a clean run of install, bootstrap, hooks, `check`, `build` and `smoke` passed on Ubuntu 26.04 LTS under WSL2 (see [Ubuntu onboarding evidence](evidence/ubuntu-onboarding-2026-11.md)). That scope is exact: bare-metal Linux, other Ubuntu releases, ARM and macOS were not exercised. CI runs on Linux. No Cloudflare login, account, database, container or secrets are needed locally.

Review `mise.toml`, then trust it through your mise installation if prompted. Use explicit tool versions so unrelated globally configured tools are not installed:

```powershell
mise install bun@1.4.4 node@26.13.0
mise exec bun@1.4.4 node@26.13.0 -- bun run bootstrap
mise exec bun@1.4.4 node@26.13.0 -- bun run check
mise exec bun@1.4.4 node@26.13.0 -- bun run build
mise exec bun@1.4.4 node@26.13.0 -- bun run dev
```

`check` also needs the other pinned tools (hk, pkl, gitleaks, actionlint, zizmor, renovate), so run a plain `mise install` (or `mise install --locked`) once before it. Install the repository Git hooks once per checkout, including linked worktrees, with `mise exec -- hk install --mise`. This needs Git 2.54 or newer for config-based hooks: with an older Git, `hk install` still succeeds but writes legacy shims, and the real hook-install test is skipped (the suite stays green, so read the `SKIPPED real hk install test` line). Ubuntu 26.04 packages Git 2.53.0, so install a newer Git first (for example from source, or the Git maintainers' PPA, which is not yet verified here) and confirm `git --version`.

`bootstrap` verifies exact runtimes and installs the committed single `bun.lock` with `--frozen-lockfile`; dependency drift fails. `check` runs, in order: runtime pins; Oxfmt format check; type-aware Oxlint (see below); the core import guard; the dependency-cruiser layering gate; Knip; the Markdown link gate; the base-branch consistency gate (`branches:check`: CONTRIBUTING, workflow and plane name the same pull request base); the Worker binding type freshness check; the workflow lint (actionlint and zizmor); the Renovate configuration validator; the Bun test suite (`bun test --parallel=4`) with the per-file 100% line and function coverage threshold; the Vitest suite for `apps/api` in workerd and `apps/web` in happy-dom with a per-file 90% line, function and branch threshold (`test:vitest`, METRO-77 and METRO-79); the coverage scope gate; and every strict TypeScript project (web, DOM tests, API, API Worker tests, contracts, scripts, E2E, test tooling, core). See [METRO-12 evidence](evidence/metro-12.md) for canonical commands and budgets. `build` runs `vite build` (client assets in `apps/web/dist/client`, Worker bundle in `apps/web/dist/metro_scaffold`) and then dry-runs Wrangler against that generated configuration into `apps/api/dist`; it uploads/deploys nothing. `dev` runs Vite with `@cloudflare/vite-plugin`: the SPA and the Worker API share one origin, `http://127.0.0.1:5173`, with the Worker running in workerd and React Fast Refresh. Ctrl+C stops it. The port must be free (`strictPort` makes an occupied port fail visibly). Unknown `/api/*` returns 404 with `{ error: { code, message } }`; other unknown paths serve the SPA. See [ADR-0002](adr/0002-runtime-topology.md) and [ADR-0003](adr/0003-contracts.md).

For the Playwright Test E2E smoke after build (Chromium locally; with `CI=true` it also runs Firefox, WebKit and a mobile viewport, which need `bun run playwright install firefox webkit`):

```powershell
mise exec bun@1.4.4 node@26.13.0 -- bun run playwright install chromium
mise exec bun@1.4.4 node@26.13.0 -- bun run smoke
```

Smoke runs `playwright test` (`@playwright/test`, config in `playwright.config.ts`, specs in `e2e/`) against the built app served by `vite preview` on a free port that `scripts/smoke.ts` picks per run (`SMOKE_PORT` overrides) (web and Worker together in workerd). It checks real HTTP status and schema-valid bodies for the status route, the 404 and 405 envelopes and a deep link, renders the success state, injects a 500 to prove the `role="alert"` error state, and fails any test on a console or page error or an axe accessibility violation. No retries. Failures keep a trace, a screenshot and an HTML report (`playwright-report/`). The dry-run verifies the production Worker bundle. Playwright browser downloads are environment tooling, not part of `bootstrap`.

On this managed Windows runner, per-call temporary/profile directories changed. Native package install needed a permitted execution context and stable paths. This environment-specific setup was used; ordinary machines need not override these:

```powershell
$env:MISE_DATA_DIR = Join-Path (Get-Location) '.local/mise'
$env:BUN_TMPDIR = Join-Path (Get-Location) '.local/tmp'
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.local/browsers'
```

`.local`, dependencies, bundle outputs and Wrangler state are ignored. Use the same absolute paths when checking an exported copy, so the copy gets its own dependencies while reusing installed runtimes/browser binaries.

**Devcontainer decision (METRO-55):** none is provided. mise reproduces the pinned toolchain on Windows and Ubuntu, and a container would be a second toolchain definition with no consumer. The revisit triggers (a contributor who cannot use mise, Codespaces, CI parity problems) are in the [Ubuntu onboarding evidence](evidence/ubuntu-onboarding-2026-11.md#devcontainer-decision).

## Symlinked agent entry point

`CLAUDE.md` is a git symlink to `AGENTS.md` (one file, no import line to drift). On Windows, enable Developer Mode (or run git with symlink rights) and set `git config core.symlinks true` before cloning or re-checkout, or the link is materialised as a text file containing `AGENTS.md` and agents will not see the instructions. CI and Linux checkouts are unaffected. `scripts/repository.test.ts` (FND-H5) reads the committed link from git, so it passes either way.

## TypeScript projects and the editor

Test code is kept out of the production projects on purpose, so the repository has several project configs (`apps/web`, `apps/api`, `apps/api/tsconfig.worker-test.json`, `packages/core`, `packages/contracts`, `scripts`, `tsconfig.dom-test.json`, `tsconfig.e2e.json`, `tsconfig.test.json`). The root `tsconfig.json` is a solution file (`files: []` plus `references` to every one of them) so an editor, and the type-aware linter, open each file in the project the gates check it with. Without it a test file falls into an editor "inferred project" with no `types`, and the test globals (`test`, `expect`), `node:*`, `process` and `Bun` all show as missing. `scripts/tsconfig-projects.test.ts` fails if a project config is not referenced or a tracked `.ts`, `.tsx`, `.mts` or `.cts` file belongs to no referenced project. Add a new project config to the references. `bun run typecheck` is a single `tsc -b` over this solution file: it builds every referenced project (all nine, listed by `tsc -b --verbose`), keeps going after a failing project, exits non-zero, and prints the failing file path (not the project config). Build mode writes a gitignored `*.tsbuildinfo` beside each project config and emits nothing. `erasableSyntaxOnly` is set in `tsconfig.base.json` so the compiler rejects enums, runtime namespaces and constructor parameter properties, which Node type stripping cannot run (`scripts/tsc-build.test.ts`). `--builders` and `--checkers` stay at their defaults: TypeScript 7 documents both as experimental and the full run takes about 1.5 s.

**Editor (VS Code, Cursor).** The compiler is TypeScript 7 (`tsc`). TypeScript 7.0 ships no JavaScript API, so `@typescript/typescript6` stays as a documented side-by-side seam for the tools that need one (`scripts/boundaries.ts`, dependency-cruiser; ADR-0001) until the TypeScript 7.1 API is stable. The classic `typescript.tsdk` mechanism cannot select TypeScript 7 (it has no `tsserver.js`), so `.vscode/settings.json` enables the TypeScript 7 language server with `js/ts.experimental.useTsgo` and `.vscode/extensions.json` recommends `TypeScriptTeam.native-preview`. In Cursor, install that extension (from a VSIX if the marketplace lacks it) or the editor keeps its bundled TypeScript; both work with the solution-style root. Cursor does not apply `tsdk`-style path settings from workspace settings, so they are not set here.

Bun types `expect(promise).rejects` as `void`, which the type-aware lint reports as an unnecessary `await`. Use `expectRejection(promise, message?)` from `scripts/test-support.ts` in `scripts/` tests instead; the web tests use a plain `.then` outcome.

## Boundaries and choices

- `packages/core/src` concept folders (`geo`, `stations`, `fares`, `status`), each with its tests beside the code; `src/index.ts` is the only public entry. No dependencies, provider globals, apps or adapters. Its separate `types: []`, ES-only typecheck runs without browser/Bun/Node globals.
- `packages/contracts`: Valibot (Standard Schema v1) schemas and parsers for the status and the error envelope; it imports only core and Valibot. `apps/web`: React DOM composition and a typed fetch client; `apps/api`: Hono composition with Worker default export and the Worker configuration. Apps depend inward on contracts and core, never on each other; dependency-cruiser enforces these layers (see [architecture](agents/architecture.md)).
- `apps/api/worker-configuration.d.ts` is generated by `bun run --cwd apps/api types` (`wrangler types`, including the workerd runtime types; it is the only source of Workers types, [ADR-0014](adr/0014-language-level-and-worker-types.md)); `bun run types:check` fails when it is stale.
- Root owns build/test tooling. App manifests own runtime dependencies. Exact direct versions plus the single Bun lock pin the resolved graph; there is no workspace orchestrator.
- `scripts/boundaries.ts` parses core source imports, exports, import types, dynamic imports and require calls. It rejects non-relative/computed/escaping references, symlinks and declared dependencies. Test files may import Bun. This narrow smoke guard is not a security sandbox or full architecture policy; the import-graph and CI gates are described in [quality gates](agents/quality-gates.md).
- Node runs Vite/Wrangler tooling and native TypeScript scripts; Bun installs/tests/orchestrates. The local runtime is Vite plus `@cloudflare/vite-plugin` (no unstable Wrangler API). Upgrades of Vite, the plugin or Wrangler require rechecking dev, preview smoke and the dry-run; the Worker `compatibility_date` must not be newer than the installed workerd supports.

No station/fare functionality, provider integration, product API contract, data store, Docker/native project templates, deployment or release automation is implemented. CI quality gates exist; see [quality gates](agents/quality-gates.md). Existing preparation checks remain separate; see [reviewed skills](agents/skills.md).

## Configuration ownership

**Confirmed / Repo-verified:** `package.json` owns exact runtime metadata and direct dependency pins; `mise.toml` mirrors runtime versions and delegates task commands. `scripts/tools.ts` parses required package/mise/bunfig files, rejects malformed/missing/mismatched fields and checks effective Bun/Node versions before normal commands. `bunfig.toml` enforces exact additions, disabled automatic install, isolated linking and text lockfiles. Bootstrap explicitly uses the frozen committed lockfile. Update pins and lock together; run all gates after changes.

`bun run format:check` checks supported tracked and newly added non-ignored TypeScript, JavaScript, CSS, HTML, Markdown, JSON/JSONC, TOML and YAML using pinned Oxfmt. It never writes; `bun run format` writes source/config formatting. This checks syntax/layout, not arbitrary configuration schemas. The explicit guard checks runtime/install semantics; TypeScript, Vite and Wrangler validate their own configuration during the gates. `.editorconfig` and `.gitattributes` specify UTF-8/LF/indent policy. Ignore rules cover local secrets and generated files, while nested `.env.example` and `.dev.vars.example` remain trackable; examples must contain safe dummy values.

Shared compiler policy lives in `tsconfig.base.json`. Browser uses DOM+React types; Worker uses Cloudflare types; Node tools use Node types; scripts and package tests and Bun-only tooling use Bun types; web component tests use DOM and Node types with Vitest imports (no Bun types); core uses ES types only. All enable strict checks including unchecked indexing, exact optional properties, returns, unused declarations/parameters and explicit property access. `scripts/types.test.ts` compiles real fixture programs with positive controls and rejected foreign globals.

**Confirmed / Repo-verified compatibility exceptions (METRO-88 added two):** `scripts/tsconfig.json`, `apps/web/tsconfig.json` and `tsconfig.dom-test.json` set `skipLibCheck: true`. The two web projects load `@types/google.maps` 3.66.9, whose own declarations fail the base `exactOptionalPropertyTypes` (TS2420 at lines 13527 and 16448 of its `index.d.ts`); it is type-only and dev-only, source checking stays strict, and removing the flag makes `tsc -b` fail again. No configuration test enumerates the allowed files (checked 2026-11-07). The `scripts` exception, the first, is as follows: The scripts project type-checks `apps/web/vite.config.ts`, which imports `@cloudflare/vite-plugin`; its declarations reach Wrangler and Miniflare declarations that reference unpublished internal packages and missing modules (removing the flag was tried on 2026-11-03 and failed with TS2307 in Wrangler's `cli.d.ts`). Explicit `types: ["node"]` cannot prevent declarations reached by actual imports from being checked. Adding DOM would leak browser globals; removing typed runtime imports or introducing ambient stubs would hide API usage. Source checking stays strict and real negative source tests remain active. All other projects (every one except these three) check library declarations. TypeScript 7 supplies `tsc`; `@typescript/typescript6` supplies only the JavaScript compiler API used by the core import guard and dependency-cruiser parser. Revisit both exceptions on upgrades. See [METRO-16 evidence](evidence/metro-16.md).

## Linting and formatting

**Confirmed / Repo-verified:** Oxlint 1.90.0 runs type-aware through `oxlint-tsgolint` (the TypeScript 7 native compiler, "tsgo") with `--type-aware --deny-warnings` over `apps`, `packages`, `scripts`, `e2e` and `playwright.config.ts`. `.oxlintrc.json` enables the `correctness`, `suspicious` and `perf` categories as errors, the `eslint`, `typescript`, `unicorn`, `oxc`, `import`, `promise`, `node`, `react` and `jsx-a11y` plugins, a curated strict rule set (no `any`, no non-null assertions, no floating or misused promises, the `no-unsafe-*` family, consistent type imports, `require-unicode-regexp`, hook rules) and `reportUnusedDisableDirectives` as an error. Overrides: command-line tools may use `console` and sequential `await` loops; test files add the `jest` rules. Test files use Bun's injected globals and must not import from `bun:test`: oxlint's jest rules cannot see that import, so `eslint/no-restricted-imports` rejects it (METRO-50, see [testing](agents/testing.md)). The `no-unsafe-*` family is off for files that the nearest `tsconfig.json` does not give `bun` types (tests, `scripts/tools.ts`, `scripts/configuration.ts`), because the test globals and `Bun` would resolve to error types; `bun run typecheck` still checks those files strictly. `options.typeCheck` (experimental TypeScript diagnostics inside Oxlint) is not enabled; `tsc` stays the compiler gate.

Oxfmt 0.75.0 reads `.oxfmtrc.json` (100 columns, double quotes, trailing commas, LF, sorted imports in builtin, external, internal, relative groups, sorted `package.json`) and `.editorconfig`. It ignores build output and the generated `apps/api/worker-configuration.d.ts`. `scripts/lint-config.test.ts` fails if type-aware linting, the strict categories or import sorting are removed.
