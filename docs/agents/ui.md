## Accessibility target: WCAG 2.2 AA (METRO-41)

The target is WCAG 2.2 level AA. `bun run smoke` enforces what a browser test can; the rest stays manual. Repo-verified against axe-core 4.14.0 and @playwright/test 1.64.1, Context7-verified (Playwright aria snapshots) and Web-verified 2026-11-05 (W3C WCAG 2.2 success criteria).

- Automatic (axe, `AXE_TAGS` in `e2e/fixtures.ts`): rules tagged `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, plus `best-practice`. A tag filter replaces axe's default rule set, so `best-practice` keeps the rules axe ran before. `wcag22aa` selects only `target-size` (2.5.8 Target Size (Minimum)), which axe leaves off by default; axe cannot judge every 2.5.8 exception (inline text, equivalent control, user-agent default), so a pass is not proof. A test with 16 px adjacent buttons fails if the tag list is dropped.
- Keyboard test (`e2e/keyboard.ts`): Tab reaches every control in DOM order (2.1.1 Keyboard, 2.4.3 Focus Order), the control matches `:focus-visible` with a drawn indicator (2.4.7 Focus Visible), and nothing covers it (2.4.11 Focus Not Obscured (Minimum); the check is stricter, five sample points must hit the control). The scaffold has no interactive control, so the page test asserts zero controls and that Tab focuses nothing; the helper is proven on a page with controls and fails on hidden focus, an overlay and positive `tabindex`. WebKit does not Tab to links by default, so the helper takes `linksTabbable`; Linux WebKit behaviour is Unverified.
- ARIA snapshot (`toMatchAriaSnapshot`, inline, `/children: equal`): `main` in the success state (heading, paragraph, `status` named "Scaffold status") and in the error state (`alert`), covering 4.1.3 Status Messages through `role=alert`. The same template passes in all four projects, so there are no per-browser forks.
- Manual (record evidence, not automated): real screen-reader output and live-region timing, 1.4.10 Reflow and 1.4.4 Resize Text (320 px, 200 %), 2.4.11 against sticky or transient overlays in future UI, 2.5.7 Dragging Movements, 2.5.8 exceptions, 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication (Minimum). 2.4.13 Focus Appearance is AAA and out of scope.
