# UI and accessibility

Read when: building or changing components in `apps/web/src`, interaction, focus, error copy or accessibility checks.

## Rules

- Inspect the affected components first. For existing journeys and domain terms read [parity](../product/feature-parity.md) and the [glossary](../product/glossary.md); do not invent behavior from planned architecture.
- Specify loading, empty, success, failure and recovery states, keyboard and focus behavior, labels, screen-reader feedback and responsive checks for each UI slice. Keep geographic station selection and provider walking-route distance as distinct concepts.
- The target is WCAG 2.2 level AA. Keep the axe tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and `best-practice` (`AXE_TAGS` in `e2e/fixtures.ts`): a tag filter replaces axe's default rule set, and `wcag22aa` is what turns on `target-size`. A pass is not proof of 2.5.8.
- `bun run smoke` runs Playwright against the built app with an axe scan on every page and fails on page or console errors. It covers the app at `/` (the nearest-station reference slice) with a stubbed Maps API (see [golden path](golden-path.md)), not the real Google widget. Record manual evidence for what it does not exercise and list unrun automation: screen-reader output and live-region timing, 1.4.10 Reflow and 1.4.4 Resize Text (320 px, 200 %), 2.4.11 against overlays, 2.5.7 Dragging, 2.5.8 exceptions, 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication. 2.4.13 is AAA and out of scope.
- Keyboard: `expectTabReachesEveryControl` (`e2e/keyboard.ts`) requires Tab to reach every control with a visible `:focus-visible` indicator, nothing covering it, no trap and Shift+Tab leaving the last control. The slice pins its own counts. When controls appear the pin fails: set the new count and add ARIA snapshot and keyboard cases.
- Styling ([ADR-0021](../adr/0021-design-foundation-styling.md)): plain CSS and tokens in `apps/web/src/styles/`, loaded fonts, tokens, base, components. The entry imports only `shell.css`; a slice imports the `components/*.css` it uses, so they load with its chunk. Colours, radii, shadows, motion and layers exist only in the `tokens*.css` files (what only a lazy part uses is in `tokens-parts.css` or `tokens-map.css`), elsewhere `var(--…)`; a new token needs both themes and a pair in `scripts/design-contrast.ts`. Never an inline style, `<style>` or inline script (CSP): dynamic values use `style.setProperty` or data attributes.
- Themes: System, Light, Dark in `localStorage["msf-theme"]` (`src/theme/theme.ts`, every access in `try`/`catch`). `public/theme-boot.js` is the one pre-paint script (classic, same origin, counted by `bundle:check`); add no other head script. Both also set `theme-color` (brand.md).
- Parts: wrap a screen in `AppShell` (the header brand is the one Home link; no `nav` means no tab-bar room under the sheet; one `main`; `SectionNav` links with `aria-current`, never tabs; 44 px sheet handle; focus entering a peeking sheet opens it to half; `useSheet()` sets the snap, and the slice owns its own snap rules: typing to full, a result to half, "show on map" to peek). Draw icons with `Icon` and a named export of `icons/icon-data.ts`. Show a fare with `Price` (hides the taka sign, speaks "taka"). Fonts are Latin only; preload only what first paint uses. Keep every new animation under the reduced-motion rule in `base.css`.
- Map: `features/line-map` is the schematic SVG in the shell's `map` slot, after the panel in DOM order (lazy, pure, no network): one `role="application"` tab stop with its own keys, three 44 px buttons; icons may live in the chunk ([METRO-111](../evidence/metro-111.md)). Labels are fixed-size ([ADR-0025](../adr/0025-phone-map-fixed-size-labels.md)).
- Error handling: `main.tsx` renders `StrictMode > ErrorBoundary > AppRoutes` with `rootErrorOptions`. `ErrorBoundary` is a small class (no dependency); it catches render, lifecycle and constructor errors only, so event handlers, async callbacks and effects set their own error state. The fallback is a `main` with a `role="alert"` section named by its `h1`, a plain-English hint and a native "Try again" button; the section takes focus on mount (`tabIndex={-1}`, 3px outline from `base.css`). All fallback copy lives in `errorCopy`.
- Never render or log `error.message`, a stack or a component stack: they can carry coordinates or URLs. `report-error.ts` logs only `<label>: <name>` with one of the seven built-in error names, else `Error` or `NonError`; the three root callbacks use it. A failed request shows fixed copy keyed by error class (`copy.ts` in the feature), never the error ([security](security.md)). Setting the callbacks hides React's default console output; to debug, widen the reporter locally and never commit that.
- Read [testing](testing.md) for behavior, [security](security.md) for location and permissions, [API](api.md) for provider interaction.

## Enforced by

- `e2e/fixtures.ts`: fails any test on a console error, an uncaught page error or an axe violation (a deliberate error must use `allowedConsoleError`). `scripts/ui-docs.test.ts` fails if an axe scan bypasses `AXE_TAGS`. Fix the page, not the fixture.
- `e2e/error-fallback.e2e.ts`: fails if the fallback lacks the named alert, focus, a 2px outline, retry, or leaks the thrown message.
- `e2e/accessibility.e2e.ts`, `e2e/keyboard.ts`: fail on keyboard and ARIA snapshot regressions.
- `scripts/design-contrast.test.ts` (53 handoff pairs, both themes), `scripts/css-rules.test.ts` (no inline style, no colour literal outside `tokens.css`, load order), `e2e/design-foundation.e2e.ts` (themes, no flash, axe light and dark, preferences, sheet). Fix the token or rule, not the test.
