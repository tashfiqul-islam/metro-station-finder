# Quality gates

Status: Repo-verified configuration. Hosted execution and remote enforcement require controller verification.

Use `mise install`, then `mise exec -- bun run bootstrap` for the exact tool pins and frozen dependencies. Install repository hooks with `mise exec -- hk install --mise` in each checkout, including linked worktrees. This writes local Git hook configuration (Git 2.54+) or legacy shims; it does not enforce remote policy. Keep mise available on PATH. No global hook install required.

`hk.pkl` pins schema 2.11.0; mise pins hk 2.11.0 / Pkl 0.32.2. Pre-commit stashes unstaged edits, runs canonical `bun run check:fast` against the staged snapshot, then restores edits on success or failure. It never auto-fixes or stages changes. Format and lint also read untracked files, so unrelated untracked scratch files can fail pre-commit; this fails safe. Pre-push runs canonical `check`, `build`, `smoke`, `bundle:check` and `scan`. Hooks are local feedback and can be bypassed; CI is authoritative.

`.github/workflows/quality.yml` runs on pull requests targeting `feature/metro-rebuild` or `main`, and integration pushes to `feature/metro-rebuild`, without path filters. Three required jobs run frozen bootstrap plus check, build/browser smoke/bundle, and dependency/secret scans. The always-running `Quality gates` aggregate requires `checks`, `build` and `security` to be present and accepts only explicit success for every job in `needs`, so a job added later cannot fail silently. Missing, cancelled, skipped or failed results fail the aggregate. Actions use immutable full SHA pins, read-only contents permission and no persisted checkout credentials. There is no deployment job.

External branch rules must require the exact `Quality gates` check from GitHub Actions on `feature/metro-rebuild`, an up-to-date branch, pull requests, signed commits, resolved conversations, and no force-push/deletion or bypass. CODEOWNERS identifies @tashfiqul-islam for gate policy. CODEOWNERS alone does not enforce reviews: requiring owner approval needs a separate eligible reviewer, since the sole owner cannot approve their own PR. Controller records the actual remote rule and any approval gap; do not claim that local configuration enforces it.

Canonical checks: `bun run check:fast` (format/type-aware lint), `bun run check` (fast checks, boundaries, import graph, Knip, tests, type checks), `bun run build`, `bun run smoke`, `bun run bundle:check`, `bun run scan`. Browser smoke requires `bun run playwright install chromium` locally; CI installs browser system dependencies too. Smoke may start local services; no preview or release follows.

Focused tests cover aggregate result semantics and actual installed hooks in disposable Git repositories, including partial staging, failure restoration, linked worktrees, and pre-push blocking and allowing a push to a local bare remote. Fixture processes run without inherited `GIT_*` variables (`scripts/git-env.ts`), because Git exports `GIT_DIR` to hooks in linked worktrees and fixtures would otherwise write into the caller's repository.
