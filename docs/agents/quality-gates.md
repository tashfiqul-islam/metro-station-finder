# Quality gates

Read when: finishing or reviewing work, changing a check, hook, workflow or required status, or reporting what ran.

## Rules

- Setup per checkout, including linked worktrees: `mise install --locked`, `mise exec -- bun run bootstrap`, `mise exec -- hk install --mise`. Hooks need `mise` on PATH and write local Git hook configuration only; they enforce no remote policy. Hooks are local feedback and can be bypassed; CI is authoritative.
- Pre-commit stashes unstaged edits, runs `bun run check:fast` on the staged snapshot and restores edits on success or failure; it never auto-fixes or stages. Untracked scratch files can fail it; that fails safe. Pre-push runs `check`, `build`, `smoke`, `bundle:check` and `scan`. The `commit-msg` hook runs `scripts/commit-message.ts`: Conventional Commits (`feat|fix|refactor|docs|test|chore|perf|ci|style|build|revert`, optional scope and `!`; merge and revert subjects pass) and no `Signed-off-by` with an AI-agent address. CI checks every commit in the PR range the same way. Attribution is in [workflow](workflow.md#attribution).
- Canonical checks: `bun run check:fast` (format and type-aware lint); `bun run check` (fast checks, boundaries, import graph, Knip, link gate, `types:check`, workflow lint, Renovate validation, `bun test --parallel=4`, `bun run test:vitest`, coverage scope, `tsc -b`); then `bun run build`, `bun run smoke`, `bun run bundle:check`, `bun run scan`. Smoke needs `mise exec -- bun run playwright install chromium` locally. In CI the `Checks` job runs `bun run check:timed`, which runs exactly the commands of `check` in order with the same fail-fast behavior and prints a duration table; `package.json` stays the one source of truth.
- `.github/workflows/quality.yml` runs on PRs to `feature/metro-rebuild` or `main` and on integration pushes, without path filters. Its jobs are `changes`, `checks`, `build` and `security`. The `Quality gates` aggregate always runs, needs all four and accepts only explicit success; the one exception is a skipped `build` when `changes` reported `docs_only` as exactly `true`. `docs_only` is true only when every changed path is markdown at the root or under `docs/`; any error or other event means `false` and a full run. `build` must not use `always()` or `!cancelled()`. Never use workflow-level `paths` filters: a path-skipped required check stays Pending.
- Lab vitals: the Chromium-only `e2e/web-vitals-lab.e2e.ts` fails above LCP 2500 ms or CLS 0.1, and `bundle:check` budgets the entry chunk apart from the totals. Limits and how to read a failure: [METRO-44c](../evidence/metro-44c.md).
- Actions use full SHA pins, job-level read-only `contents` and no persisted checkout credentials. Caches are restored only in jobs without credentials. Superseded runs are cancelled only for pull requests. The only deployment job is the credentialed `preview` job. Keep the job name `Quality gates` stable; coordinate required-check policy before renaming.
- External branch rules must require both exact checks, `Quality gates` and `Reviewer record`, from GitHub Actions on `feature/metro-rebuild` and on `main`, plus an up-to-date branch, pull requests, signed commits, resolved conversations and no force-push, deletion or bypass. CODEOWNERS names @tashfiqul-islam for gate policy but cannot force owner approval (the sole owner cannot approve their own PR). Record the actual remote rule and any gap; never claim local configuration enforces it.
- Dependency review (`.github/workflows/dependency-review.yml`) is advisory: it fails a PR that adds a dependency with a `high` or worse vulnerability, is not part of `Quality gates` and is not a required check until the owner adds `Dependency review` to both rulesets. Do not add it to `needs` of `quality` without that decision. The dependency graph must stay enabled or the job fails red. GitHub security settings are read by the owner-run `bun run github:settings` ([runbook](github-settings.md)).
- Hook bypass: none by default. Agents never bypass hooks or signing; fix the failure. Never use `git commit --no-verify` or `git push --no-verify`, and never turn off signing. The one exception is an owner-only emergency skip of a single named step (`fast`, `conventional`, `check`, `build`, `scan`) for that one command only, never in a profile, `git config` or `.hkrc.pkl`, which would persist it; CI still runs and the step is listed under "Checks not run". PowerShell: `$env:HK_SKIP_STEPS = 'build'; git push; Remove-Item Env:HK_SKIP_STEPS`. Shell: `HK_SKIP_STEPS=build git push`.
- Signatures: GitHub's "Verified" badge is authoritative; locally inspect `git config --get gpg.format`, `commit.gpgsign`, `gpg.ssh.allowedSignersFile` and `git verify-commit HEAD`. With SSH signing a signer must be in the allowed-signers file; "No public key" is a local keyring gap, not proof of a bad signature.
- Report exact revision, commands and outcomes; a local pass is not hosted CI proof. Fixture git processes run without inherited `GIT_*` variables (`scripts/git-env.ts`).

## Enforced by

- `scripts/ci-results.ts` and `scripts/changes-workflow.test.ts`: fail the aggregate on a missing, cancelled or unexpectedly skipped job. `scripts/changed-files.ts` decides `docs_only`; extend its allow-list only with a reviewed change and a test.
- `scripts/hooks.test.ts`, `scripts/hooks-status.ts`, `scripts/timed-check.test.ts`: fail on hook, restoration or `check:timed` drift. `scripts/workflows.ts` (`lint:workflows`) and `scripts/ci-hardening.test.ts` fail on unpinned or over-privileged workflows. Fix the workflow, not the check.
- `scripts/dependency-review-workflow.test.ts`: fails if the advisory workflow gains secrets, caches or a place in `quality.yml`.
