# Plane

Read when: reading, preparing, publishing or changing Plane tickets, specs, labels, states or releases.

## Rules

- Plane (workspace `metro-station-finder`, project METRO, UUID `1ab13b1b-d537-4524-8f18-45ee42262dc4`) holds tickets and PRDs through the connected Plane MCP tools; GitHub is the code host only (no `gh issue`). Inspect the live tool schema first; schemas change. This guide authorizes no writes: research, then settled spec, approved slices, authorized publishing, readiness review, separately authorized implementation. No parallel dispatch is implied.
- Use full UUIDs in arguments; resolve `METRO-NN` through `workitem.retrieve_by_identifier`. Never infer UUIDs from names. Do not mix raw REST and connector argument shapes.
- Before `page.update`, retrieve the Page and preserve its content and reviewed source revision; never overwrite concurrent edits. Create a Page with `parent_id` or `collection_id`, never both; detach with the returned work-item-page link ID, not the Page UUID. Store a settled spec as a project Page from the [specification template](../templates/specification.md). Record the immutable source revision, decisions, exclusions and criterion and seam IDs in every ticket; a link to a mutable Page is not provenance. Ticket bodies follow the [ticket template](../templates/plane-ticket.md).
- States: Backlog, Specifying, Ready, In Progress, In Review, Done, Cancelled. Match names with `state.list` and use the returned UUID. Do not create or rename states or duplicate Ready as a label. System Triage is reserved: only the owner or Plane automation places items there. An unevaluated agent-created item starts in Backlog.
- Triage roles map to states, not labels: `needs-info` is Specifying plus `blocked`; `ready-for-agent` and `ready-for-human` are Ready, with `Implementation mode: AFK` or `HITL` in the ticket's "Evidence and readiness" section; `wontfix` is Cancelled plus a reason comment.
- Dependencies are native `blocked_by` relations created on the dependent item (`workitem_ids` array); read back both ends. Never use body links or `relates_to` instead; never remove a dependency just to reach Ready.
- Modules, milestones and releases: resolve an existing one and use the `manage_workitems` action (one UUID string per `add_ids` call), then verify with `list_workitems`. Creating or changing groups needs explicit scope; report a missing group, do not invent it. A release is workspace scoped; `release_date` maps to the UI Target date; never substitute the hidden `target_date`. Source and group links do not substitute for native membership. Assignment means intended shipping, not shipped.
- Labels classify; they never duplicate a state, module, milestone, release or type. Exactly one `area:*` set at creation: `area:agents`, `area:api`, `area:delivery`, `area:docs`, `area:domain`, `area:tooling`, `area:web`. Zero or more `quality:*`: `accessibility`, `observability`, `security`, `testing`. Status flags only while true: `needs-decision` (an open material choice; resolve before Ready), `needs-owner-action` (a step only the owner can do outside the repo) and `blocked` (needs a `blocked_by` relation and an explanation). Remove a flag when resolved or when the item is Done or Cancelled. New labels need owner approval and a one-line description.
- Publishing: confirm authorization names the spec, slices and writes. Keep a ledger (stable key, returned UUID or URL, body revision, Page link, relations, memberships, state, readback; never tokens). Identity is `external_source = metro-spec`, `external_id = <specification-id>/<slice-id>`; search both fields in the project, follow all cursors, include archived items. Create only when lookup completed and found nothing; one match is retrieved and compared; several matches, a timeout, a conflict or incomplete paging means stop and reconcile by hand. A create timeout is not proof nothing exists; never retry a create blindly or merge or delete duplicates automatically.
- Create blockers before dependents, in Backlog or Specifying. Record each returned ID at once, read back, and on restart reconcile the ledger first. No automatic destructive rollback. Preserve scope, exclusions, criterion IDs, seams and blockers from the spec; use the [local dry run](../examples/plane-preparation/README.md) first (it checks preservation, not correctness).
- Move to Ready only when authorized and the readiness review passes ([workflow](workflow.md)). Done needs fresh acceptance evidence, resolved review, available CI and authorized merge policy. Ticket merges target `feature/metro-rebuild`; the owner's integration exception applies as written in the workflow. The base branch named here changes at [cutover runbook](cutover-runbook.md) step 6.4 together with CONTRIBUTING.md and workflow.md.
- The Plane GitHub integration links PRs naming `METRO-NN` but did not move any state in tests. Do not rely on it: move states by hand and post the closing comment. Reconcile any premature Done. Never set Issue Sync to Bidirectional (it would copy tickets into the public repository).
- A missing connector capability is a stop condition: report the limit, keep the ledger, get an authorized route. Remote idempotency and permissions were not write-tested; assume no transactions or duplicate protection.
