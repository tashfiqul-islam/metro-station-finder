Historical baseline: legacy implementation references and checks below concern commit `af903d7a2c1bf08165cfcf4a00ca0c0d73eedead`, not files or executable gates in this independent rebuild. See [rebuild boundary](../../README.md).

Read on secrets, coordinates, permissions, external input or provider changes. Inspect affected call sites and config; [script loader](https://github.com/tashfiqul-islam/metro-station-finder/blob/af903d7a2c1bf08165cfcf4a00ca0c0d73eedead/src/utils/loadGoogleMapScript.ts) illustrates browser provider access, not a security audit.

Use synthetic data in evidence. Do not record personal locations, addresses, credentials or secret-bearing request URLs. Public browser configuration is visible to clients; verify provider restrictions and handling against official docs for an authorized change, never claim secrecy from an environment-variable name. Contract/permission changes need explicit scope.

Specify validation and observable denial/provider-failure behavior; avoid silent catch-and-continue paths. Do not introduce logging of sensitive inputs while diagnosing. `bun run scan` audits dependencies (`bun audit`) and scans tracked files for secrets with the pinned Gitleaks, locally and in the CI `security` job. The scan refuses tracked symlinks and submodules except a symlink whose target is a plain relative name of another tracked regular file (read from the git object, never followed outside the repository), such as `CLAUDE.md` pointing at `AGENTS.md`; the target is scanned as itself (see [quality gates](quality-gates.md)). Install scripts (METRO-46): the root `package.json` declares `"trustedDependencies": []`, so no dependency runs a lifecycle script on install. Without the field Bun runs scripts for packages on its built-in default list; declaring it, even empty, replaces that list ([Bun lifecycle docs](https://bun.com/docs/pm/lifecycle), read 2026-11-04). `package.json` `trustedDependencies` is authoritative and is enforced by the repository gate (`scripts/configuration.ts`); `bun.lock` records the value for information and diffs and is not an enforcement point (a frozen install against an older lockfile without the field still succeeds and still blocks the scripts). `esbuild` and `workerd` have blocked `postinstall` scripts; build, tests and the Playwright smoke pass without them. To trust a package, add its exact name to the array in the same change as the entry in `REVIEWED_TRUSTED_DEPENDENCIES` in `scripts/configuration.ts`, run `bun install` to update `bun.lock`, re-run `mise exec -- bun pm untrusted` to confirm the package left the blocked list, confirm build and tests still pass, and record why the script is needed and what it does (reviewed against the package source) in the pull request and [maintenance](maintenance.md). List what is blocked with `bun pm untrusted`. Accepted gap: nothing fails automatically when a future dependency needs its install script; Bun only prints "Blocked N postinstall" and `bun pm untrusted` lists them, so a reviewer should run it whenever dependencies change. A passing scan is not a security clearance: it does not cover application logic, permissions or runtime configuration.
