# Testing and bugs

**Confirmed / Repo-verified (legacy baseline `af903d7`):** [manifest](https://github.com/tashfiqul-islam/metro-station-finder/blob/af903d7a2c1bf08165cfcf4a00ca0c0d73eedead/package.json) has no test script. The legacy baseline had no test runner.

**Confirmed / Repo-verified:** the independent rebuild runs a layered, coverage-enforced suite: Bun unit, component and in-process API tests through root `check`, standalone typechecks, and Playwright Test E2E through `smoke`; CI runs all of them (see [quality gates](quality-gates.md)). See [commands and limits](../development.md). These checks do not prove product parity or full accessibility conformance.

## Test layers and conventions

| Layer                           | Where                                  | Run with                              | Notes                                                                                                                                                               |
| ------------------------------- | -------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit (core, contracts, scripts) | colocated `*.test.ts`                  | `bun test` (part of `check`)          | No network, clock or randomness without a seam.                                                                                                                     |
| API in process                  | `apps/api/src/*.test.ts`               | `bun test`                            | Hono `app.request()`; asserts status, body, schema validity, envelopes and methods.                                                                                 |
| Component                       | `apps/web/src/*.test.tsx`              | `bun test`                            | `@happy-dom/global-registrator` registered before React and Testing Library load; `fetch` is stubbed; typechecked by `tsconfig.dom-test.json` (DOM plus Bun types). |
| E2E and accessibility           | `e2e/*.e2e.ts`, `playwright.config.ts` | `bun run build`, then `bun run smoke` | Playwright Test against the built `vite preview` (workerd). Locally Chromium only; with `CI=true` Chromium, Firefox, WebKit and a mobile viewport.                  |

- Test files are colocated with the code they test (`*.test.ts`, `*.test.tsx`); E2E specs live in `e2e/`.
- Fixtures are synthetic. Never use real locations, addresses or credentials. Unit and component tests make no network calls.
- Determinism: no retries (`retries: 0` everywhere; a flaky test is a defect), no sleeps as synchronization (wait on observable state), fixture git processes use `cleanGitEnv()`, temporary directories are removed in `finally`.
- Randomized order (METRO-35): `bunfig.toml` sets `[test] randomize = true` and never a `seed`, so every `bun test` run picks a new seed and prints it in the summary (` --seed=N`). CI's Playwright run uses `bun run smoke -- --shuffle`, which prints `Running N tests using W workers, shuffle seed S`. `scripts/configuration.ts` (via `check`) fails when `randomize` is absent or a fixed `seed` is set; `scripts/test-order.test.ts` proves with a temporary order-coupled fixture under `.local/` that a seed exposes coupling and reproduces it. Tests must not depend on file or declaration order: keep state per test, restore globals and `process.exitCode`, and use per-test temporary directories.
- Reproduce a failure from a CI log: copy the seed and run the full `bun test --seed N` first (Bun; `--seed` implies `--randomize`). Bun shuffles files as well as the tests inside a file with one seeded PRNG, so only the full run is guaranteed to reproduce the order; narrow to one file only afterwards, and expect a narrowed run to differ (it may pass or fail differently). For Playwright use `bun run smoke -- --shuffle S` (set `CI=true` to run every project). Playwright has no config key for shuffle in 1.64.1, only the CLI flag, so the CI step passes it. Fix the coupling in the test; never remove `randomize`, pin a seed in `bunfig.toml`, or loosen an assertion.
- Coverage: `bun test` enforces `lines` and `functions` at 0.9 per file (`bunfig.toml`) and writes `coverage/lcov.info`. There are no `coveragePathIgnorePatterns`. Bun reports only files a test loads, so structure scripts as a testable module plus a one-line entry guard; do not load entry files that run on import. Files no test loads are not measured at all (`scripts/bundle.ts`, `dependency-parser.ts`, `format.ts`, `secrets.ts`, `tools.ts` and the type-only `packages/core/src/domain/scaffold-status.ts`); they are exercised through subprocess tests, `check` and `smoke` instead, and any new logic should live in a loaded, tested module.
- Branch coverage (METRO-50): there is no branch gate, because Bun cannot measure branches. Repo-verified with Bun 1.4.4: `bun test --coverage --coverage-reporter=lcov` writes only `TN`, `SF`, `FNF`, `FNH`, `DA`, `LF`, `LH` records, never `BRF`, `BRH` or `BRDA`. Context7-verified: Bun's docs name only `lines` and `functions` as enforced thresholds (`statements` is accepted but not enforced) and say nothing of branches. Web-verified 2026-11-05: branch reporting is an open Bun pull request ([oven-sh/bun#46534](https://github.com/oven-sh/bun/pull/46534)), not released (merge status Unverified beyond that search). `scripts/coverage.test.ts` holds a tripwire that fails when Bun starts emitting branch records; when it does, replace the tripwire with a 90 percent per-file branch threshold in `bunfig.toml` and a failing fixture. Until then, coverage proves a line ran, not that its outcomes were asserted: the lint rules below are the guard against tests that execute code without proving anything.
- Test hygiene lint (METRO-50): `.oxlintrc.json` enables the `jest/*` rules for `*.test.ts(x)`, each with a one-line justification beside it. Oxlint's jest rules recognise only Jest and Vitest imports, so a file importing from `bun:test` is invisible to every `jest/*` rule (Repo-verified on oxlint 1.90.0: the same assertion-free test is flagged without the import and silent with it; upstream request [oxc#23290](https://github.com/oxc-project/oxc/issues/23290), Web-verified). Tests therefore use Bun's injected globals (`test`, `expect`, `describe`, hooks, `jest.spyOn`), typed by `bun-types/test-globals` in `tsconfig.test.json` and `tsconfig.dom-test.json`, and `eslint/no-restricted-imports` rejects `import ... from "bun:test"` so the rules cannot go blind again. `scripts/test-hygiene.test.ts` lints a fixture per rule with the real config and proves the rejection, including an assertion-free test. Enabled: `expect-expect` (with `expectRejection` as an assertion helper), `no-conditional-expect`, `no-standalone-expect`, `valid-expect` (`maxArgs: 2` is a deliberate, documented relaxation: Bun's `expect(value, "message")` accepts a custom failure message, so the second argument is valid; it does not weaken the check, which still rejects a missing matcher or argument), `valid-expect-in-promise`, `require-to-throw-message`, `no-focused-tests`, `no-disabled-tests`, `no-test-prefixes`, `no-commented-out-tests`, `valid-title`, `no-identical-title`, `valid-describe-callback`, `no-export`, `no-done-callback`, `no-duplicate-hooks`, `no-unneeded-async-expect-function`, `no-alias-methods`, `prefer-called-with`. Fix a finding by strengthening the test, never with a disable comment (`reportUnusedDisableDirectives` is on) or by dropping the rule.
- Rejected rule sets (METRO-50, measured on this repository at the time): the `pedantic` category (474 findings over 24 rules; 305 are `prefer-readonly-parameter-types` and 55 `no-confusing-void-expression`, none of which finds a weak test) and the `style` category (4920 findings, many contradicting each other or the formatter, such as `sort-keys`, `no-magic-numbers`, `one-var`). Individual rules rejected: `jest/prefer-strict-equal` (170 findings, `toEqual` is deliberate for plain data), `jest/prefer-expect-resolves` (50; Bun's types declare `.resolves` as `void`, which `typescript/await-thenable` rejects), `jest/no-conditional-in-test` (133), `jest/prefer-each` (36), `jest/prefer-ending-with-an-expect` (178), `jest/prefer-expect-assertions` (558), `jest/max-expects` (78), `jest/no-hooks`, `jest/require-hook`, `jest/prefer-lowercase-title` (451), `jest/consistent-test-it` (39) and `jest/padding-around-test-blocks` (formatter territory): noise or style without a weak-test signal. Rules with no findings and no weak-test signal (`prefer-to-be`, `prefer-to-contain`, `prefer-equality-matcher`, `prefer-comparison-matcher`, `prefer-hooks-on-top`) are left off until a case appears. `typescript/require-await` (3 findings, one in production code) and `typescript/prefer-promise-reject-errors` (3, deliberate in tests that reject with a plain value) stay off for the same reason.
- E2E fixtures (`e2e/fixtures.ts`) apply to every test in every project: any console error or uncaught page error fails the test, and any page left open must have zero axe violations. A test that provokes an error on purpose declares it with the `allowedConsoleError` option.
- Failures keep evidence: trace and screenshot on failure and an HTML report in `playwright-report/` (CI uploads both as the `playwright-report` artifact; the lcov file is the `coverage-lcov` artifact).

For bugs reproduce observed failure before a fix; record base revision, expected behavior and smallest relevant source path. Read parity evidence for existing behavior and domain glossary for terms in [feature parity](../product/feature-parity.md) and the [glossary](../product/glossary.md). Add API/UI/security/observability reads only when those boundaries are touched.

Retain settled test seams: deterministic domain/data fixtures, provider/contract boundaries, Workers integration and browser/accessibility journeys when their implementations exist. Cover invalid input, empty data, failed provider and recovery when relevant; use synthetic coordinates, never personal location. A failing regression should prove behavior, not mirror implementation. Do not weaken assertions or skip failures to pass. Record exact checks, fixtures, outcomes and omissions against [quality gates](quality-gates.md). Documentation tasks verify links, routing and scope without claiming app checks ran.

- Component test DOM (METRO-58): Bun runs every test file in one process and caches modules, and React and Testing Library bind to the globals present when first imported. Unregistering happy-dom per file made `findBy*` time out in whichever file ran second (measured, seed dependent). Registering it once and leaving it on is worse: it replaces 36 of Bun's globals (measured: `fetch`, `Request`, `Response`, `Headers`, `URL`, `AbortController`, `AbortSignal`, timers, `Event`, ...) and adds about 500 more, so every non-DOM test in the process would run against happy-dom. `apps/web/src/dom-test-env.ts` therefore registers once, snapshots the globals before and after, and exposes `enableDomGlobals()` / `restoreBunGlobals()`. A DOM test file imports it, calls `enableDomGlobals()`, imports React and the code under test, calls `restoreBunGlobals()` straight away, then calls `enableDomGlobals()` in `beforeAll` and `restoreBunGlobals()` in `afterAll`. `dom-test-env.test.ts` pins that Bun's native globals are in place outside those windows and that the swap is reversible. Checked on 12 seeds of `bun test apps packages`.
- Entry files that run on import: `apps/web/src/main.test.tsx` is the one sanctioned exception to "do not load entry files that run on import". `main.tsx` has no testable seam (it only wires `StrictMode`, the boundary and `createRoot` to `#root`), and the ticket requires proving that wiring, so the test creates `#root`, imports `main.tsx` inside the DOM window and removes the container afterwards. Keep any logic out of `main.tsx`; put it in a tested module.
- Test runner decision (METRO-74): [ADR-0016](../adr/0016-test-runner.md) accepts Vitest for the API (workerd) and web test projects, with scripts and packages decided later by a stated criterion, on the strength of a [measured spike](../evidence/vitest-spike-2026-11.md) (branch coverage under a per-file gate, workerd for the API, no happy-dom swap). The decision is accepted but nothing has moved yet: until the implementation tickets land, everything above stays in force.
