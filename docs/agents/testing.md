# Testing and bugs

Read when: writing or changing tests, fixing a bug, reproducing a CI failure or changing a test runner, coverage or lint setting.

## Rules

- Layers (all in `check`, all in CI): unit tests for core, contracts and scripts run with `bun test` as colocated `*.test.ts`; `apps/api/src/*.test.ts` run in workerd and `apps/web/src/*.test.ts(x)` in happy-dom, both with `bun run test:vitest`; browser and accessibility journeys are `e2e/*.e2e.ts` run by `bun run build` then `bun run smoke` (Chromium locally; with `CI=true` also Firefox, WebKit and a mobile viewport). These checks do not prove product parity or full accessibility conformance.
- Layout (owner decision): each unit, component or integration test sits next to its source; browser tests live in `e2e/`. A shared helper stays in the project that uses it until two packages need it; there is no `packages/test-utils` before that. Configuration, not name, decides the runner: `vitest.config.ts` projects list what Vitest runs and `bunfig.toml` `[test] pathIgnorePatterns` keeps Bun off those files.
- Coverage gates: Bun enforces `lines` and `functions` at 0.9 per file with no `coveragePathIgnorePatterns`; Vitest (istanbul, one run) enforces `lines`, `functions` and `branches` at 90 per file for every file under `apps/*/src`. Bun cannot measure branches, so lint rules guard weak tests there. Bun reports only files a test loads: write scripts as a testable module plus a one-line entry guard and never load an entry that runs on import. Exception: `apps/web/src/main.test.tsx` imports `main.tsx` after `vi.resetModules()` to prove its wiring; keep logic out of `main.tsx`.
- Order: `bunfig.toml` sets `randomize = true` and never a `seed`; `vitest.shared.ts` sets `sequence.shuffle: true` and never a `seed`, and every Vitest config spreads `sharedTestOptions` (a project does not inherit the root option). Playwright in CI uses `bun run smoke -- --shuffle`. Tests must not depend on file or declaration order: keep state per test, restore globals and `process.exitCode`, use per-test `mkdtemp` directories.
- Reproduce a CI failure from the printed seed: run the full `bun test --parallel=4 --seed N` first; if it does not reproduce, try serial `bun test --seed N`, and treat a timing-dependent failure as possible; narrow to one file only afterwards (a narrowed run may differ). Vitest: `bun run test:vitest -- --sequence.seed=N`. Playwright: `bun run smoke -- --shuffle S` with `CI=true`. Fix the coupling in the test; never remove `randomize`, pin a seed or loosen an assertion.
- `check` runs `bun test --parallel=4` with isolation on; never `--no-isolate`. Parallel safety: no fixed paths or process-wide state, `cleanGitEnv()` from `scripts/git-env.ts` for any git fixture, directories removed in `finally`, and an explicit timeout on a test that spawns a process.
- Determinism: no retries (`retries: 0`; a flaky test is a defect), no sleeps as synchronization (wait on observable state), no network, clock or randomness without a seam. Fixtures are synthetic: never real locations, addresses or credentials.
- Hygiene: tests use Bun's injected globals (`bun-types/test-globals`) and never import from `bun:test`, because oxlint's `jest/*` rules cannot see that import. Vitest files import from `"vitest"` (globals off). Fix a lint finding by strengthening the test, never with a disable comment or by dropping the rule. Web tests call `cleanup()` themselves and set `IS_REACT_ACT_ENVIRONMENT` in `beforeAll`.
- Version sync: `vitest`, `@vitest/coverage-istanbul` and `@cloudflare/vitest-plugin` are exact pins; `vitest` equals its coverage package and sits inside the plugin's peer range; Renovate groups them. The API Vitest project reads the real `apps/api/wrangler.jsonc`; no second `wrangler.*.jsonc`. `scripts/` and `packages/` may not import from `vitest`; shrink that override as stages move, never list `apps/api` or `apps/web`.
- E2E fixtures (`e2e/fixtures.ts`) apply to every test: a console error, an uncaught page error or a page left open with an axe violation fails it. A deliberate error uses `allowedConsoleError`. Failures keep a trace, screenshot and `playwright-report/`.
- Bugs: reproduce the observed failure before a fix; record base revision, expected behavior and the smallest relevant source path. A failing regression proves behavior, not implementation. Keep settled seams (deterministic fixtures, provider and contract boundaries, Workers integration, browser journeys). Cover invalid input, empty data, failed provider and recovery. Never weaken or skip to pass. Record exact checks and omissions ([quality gates](quality-gates.md)); documentation tasks verify links and routing without claiming app checks ran. Read [parity](../product/feature-parity.md) and the [glossary](../product/glossary.md) for existing behavior.

## Enforced by

- `scripts/configuration.ts` (in `check`): fails on a missing `randomize`, a fixed `seed`, a Vitest config that does not spread `sharedTestOptions` or sets `seed` or `shuffle: false`, and a root `projects` directory Bun does not ignore.
- `scripts/coverage.test.ts`: fails if `--no-isolate` enters the check script, if an uncovered file passes the gate, or if Bun starts emitting branch records (then add a branch threshold).
- `scripts/vitest-sync.test.ts`, `scripts/test-order.test.ts`, `scripts/test-hygiene.test.ts`, `scripts/coverage-scope.ts`: fail on the drift each names. Fix the code or test, not the check.
