# Testing and bugs

**Confirmed / Repo-verified (legacy baseline `af903d7`):** [manifest](https://github.com/tashfiqul-islam/metro-station-finder/blob/af903d7a2c1bf08165cfcf4a00ca0c0d73eedead/package.json) has no test script. The legacy baseline had no test runner.

**Confirmed / Repo-verified:** the independent rebuild runs a layered, coverage-enforced suite: Bun unit tests plus Vitest API tests in workerd (METRO-77) and Vitest component tests in happy-dom (METRO-79) through root `check`, standalone typechecks, and Playwright Test E2E through `smoke`; CI runs all of them (see [quality gates](quality-gates.md)). See [commands and limits](../development.md). These checks do not prove product parity or full accessibility conformance.

## Test layers and conventions

| Layer                           | Where                                  | Run with                              | Notes                                                                                                                                                                                      |
| ------------------------------- | -------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Unit (core, contracts, scripts) | colocated `*.test.ts`                  | `bun test` (part of `check`)          | No network, clock or randomness without a seam.                                                                                                                                            |
| API in workerd (METRO-77)       | `apps/api/src/*.test.ts`               | `bun run test:vitest` (in `check`)    | Vitest through `@cloudflare/vitest-plugin`, inside workerd; Hono `app.request()` plus one `exports.default.fetch` test; imports from `vitest`, globals off.                                |
| Component (METRO-79)            | `apps/web/src/*.test.ts(x)`            | `bun run test:vitest` (in `check`)    | Vitest project `web` with `environment: "happy-dom"`; imports from `vitest`, globals off; `fetch` is stubbed; typechecked by `tsconfig.dom-test.json` (DOM plus Node types, no Bun types). |
| E2E and accessibility           | `e2e/*.e2e.ts`, `playwright.config.ts` | `bun run build`, then `bun run smoke` | Playwright Test against the built `vite preview` (workerd). Locally Chromium only; with `CI=true` Chromium, Firefox, WebKit and a mobile viewport.                                         |

- Layout rule (owner decision, METRO-77): each unit, component and integration test sits next to its source as `<file>.test.ts` or `<file>.test.tsx`; browser tests live in `e2e/`. A shared test helper stays inside the project that uses it until two packages need the same helper; there is no `packages/test-utils` before that. Which runner owns a file is set by configuration, not by name: `vitest.config.ts` projects list what Vitest runs, and `bunfig.toml` `[test] pathIgnorePatterns` keeps Bun off those files.
- What runs where (ADR-0016 stages 1 and 2): `bun test` runs every test except `apps/api/**` and `apps/web/**` (scripts and packages) and enforces `lines` and `functions` at 0.9 per file; `vitest run --coverage` (`bun run test:vitest`) runs the `apps/api` project inside workerd and the `apps/web` project in happy-dom, and enforces `lines`, `functions` and `branches` at 90 per file for every file under `apps/*/src`. Both are in `check` and in CI (`Checks` job), and `check` fails if either fails. Vitest cannot mix coverage providers in one run and V8 coverage is unsupported in workerd (Web-verified, Cloudflare known-issues page), so the whole Vitest run uses istanbul and writes one `coverage/vitest/lcov.info` (web branch numbers equal V8's, measured in [the METRO-79 evidence](../evidence/metro-79.md)); CI uploads both lcov files in the `coverage-lcov` artifact. `scripts/configuration.test.ts` fails if a directory listed in the root `projects` is not ignored by Bun. `scripts/coverage-scope.ts` reads both. The Worker tests have their own TypeScript project, `apps/api/tsconfig.worker-test.json` (plugin types plus the generated Worker types), because the Bun-typed test project cannot hold `cloudflare:workers`.
- Vitest order and seed: `vitest.shared.ts` sets `sequence.shuffle: true` and never a `seed`, and every Vitest config spreads it; every run prints `Running tests with seed "N"`, and `bun run test:vitest -- --sequence.seed=N` reproduces the order (Repo-verified in `scripts/test-order.test.ts`). `scripts/configuration.ts` (via `check`) fails when `vitest.shared.ts` lacks `shuffle: true`, when a Vitest config does not spread `sharedTestOptions`, or when any Vitest config sets a `seed` or `shuffle: false`. It reads the config text with comments removed, so it is a guard on the written option, not on the evaluated config.
- Version sync (METRO-77): `scripts/vitest-sync.test.ts` fails unless `vitest`, `@vitest/coverage-istanbul` and `@cloudflare/vitest-plugin` are exact pins, `vitest` equals its coverage package, the plugin's own `miniflare` and `wrangler` resolve one `workerd` in `bun.lock`, the plugin's `wrangler` shares major.minor with the repository's, and Renovate groups `vitest` with `@vitest/**` and `wrangler` with `@cloudflare/**` (the plugin). The repository's own `wrangler` and `workerd` (build, preview) may sit a few days behind the plugin's: the test pool runs the plugin's workerd, the deployed Worker runs Cloudflare's. The API Vitest project reads the real `apps/api/wrangler.jsonc` (single source for name, entry, compatibility date and assets routing) and supplies only the assets directory (`apps/api/test-assets`, a fixture), because `@cloudflare/vite-plugin` fills it in the real build; the same test file fails if a second `wrangler.*.jsonc` appears. Every Vitest config spreads `sharedTestOptions` from `vitest.shared.ts`: a project does not inherit the root `test.sequence` (measured in workerd: with `shuffle` only in the root, tests inside a file kept their order), and `scripts/configuration.ts` enforces it.
- Vitest guards (METRO-80, [evidence](../evidence/metro-80.md)): `scripts/vitest-sync.ts` also fails when the pinned `vitest` is outside the `vitest` peer range that `bun.lock` records for the pinned `@cloudflare/vitest-plugin` (checked with `Bun.semver.satisfies`). `.oxlintrc.json` bans imports from `vitest` and `@vitest/*` in `scripts/` and `packages/` (still run by `bun test`); shrink that override's `files` list as stages move them, never list `apps/api` or `apps/web`. `apps/api/raw-modules.d.ts` stays because `vite/client` does not typecheck beside the Worker types.
- Test files are colocated with the code they test (`*.test.ts`, `*.test.tsx`); E2E specs live in `e2e/`.
- Fixtures are synthetic. Never use real locations, addresses or credentials. Unit and component tests make no network calls.
- Determinism: no retries (`retries: 0` everywhere; a flaky test is a defect), no sleeps as synchronization (wait on observable state), fixture git processes use `cleanGitEnv()`, temporary directories are removed in `finally`.
- Randomized order (METRO-35): `bunfig.toml` sets `[test] randomize = true` and never a `seed`, so every `bun test` run picks a new seed and prints it in the summary (` --seed=N`). CI's Playwright run uses `bun run smoke -- --shuffle`, which prints `Running N tests using W workers, shuffle seed S`. `scripts/configuration.ts` (via `check`) fails when `randomize` is absent or a fixed `seed` is set; `scripts/test-order.test.ts` proves with a temporary order-coupled fixture under `.local/` that a seed exposes coupling and reproduces it. Tests must not depend on file or declaration order: keep state per test, restore globals and `process.exitCode`, and use per-test temporary directories.
- Parallel Bun run (METRO-82, [evidence](../evidence/metro-82.md)): `check` runs `bun test --parallel=4` (isolation on, so each file has its own globals and module registry; never `--no-isolate`, and `scripts/coverage.test.ts` fails if the check script carries it). The count is fixed at 4 because that is the hosted runner's core count and it keeps local, pre-push and CI on one command; the value is local speed: serial 95.3 s to 37.4 s at 4 workers on a 20-core machine (28.9 s with `bun test --parallel`, all cores). On the hosted runner the gain is small and inside run-to-run noise (`bun test` rows 63.8, 98.6, 78.5 and 92.4 s parallel against 98.7 and 80.0 s serial; one probe job showed 80 s serial against 61 to 64 s at 2, 4, 8 and default workers, a single sample per mode), so do not expect a large CI saving. Bun merges the workers' coverage into one `coverage/lcov.info` (same files and per-file hit lines as a serial run, proven in the evidence) and the per-file gate still fails an uncovered file (`scripts/coverage.test.ts` runs its fixtures with the flags it reads from `scripts.check`). Every parallel-safety rule above applies harder now: per-test `mkdtemp` directories (never a fixed path), no process-wide state, `cleanGitEnv()` for git, and an explicit timeout on a test that spawns a process (one observed flake: `METRO-62 real git ranges` once took over 5 s at 20 workers against 0.4 s alone; six more sites got the same timeout as a precaution after a `--timeout=1000` stress run, and tests that run did not flag still use the 5 s default). `--timings` was measured and not adopted (no gain, the file would change on every run).
- Reproduce a failure from a CI log: copy the seed and run the full `bun test --parallel=4 --seed N` first (Bun; `--seed` implies `--randomize`). Measured in a small experiment (METRO-82: eight tiny files, seed 12345 and one other seed, two serial, three 4-worker and one 2-worker run): the order of tests inside a file followed the seed in every run. Which worker takes which file and how files interleave depend on timing and the worker count, and are not guaranteed to reproduce even with the same `--parallel=4`. If a seeded parallel run does not reproduce the failure, try a serial `bun test --seed N`, and treat a timing-dependent failure as possible. Narrow to one file only afterwards, and expect a narrowed run to differ (it may pass or fail differently). For Playwright use `bun run smoke -- --shuffle S` (set `CI=true` to run every project). Playwright has no config key for shuffle in 1.64.1, only the CLI flag, so the CI step passes it. Fix the coupling in the test; never remove `randomize`, pin a seed in `bunfig.toml`, or loosen an assertion.
- Coverage: `bun test` enforces `lines` and `functions` at 0.9 per file (`bunfig.toml`) and writes `coverage/lcov.info`. There are no `coveragePathIgnorePatterns`. Bun reports only files a test loads, so structure scripts as a testable module plus a one-line entry guard; do not load entry files that run on import. Files no test loads are not measured at all (`scripts/bundle.ts`, `dependency-parser.ts`, `format.ts`, `secrets.ts`, `tools.ts` and the type-only `packages/core/src/domain/scaffold-status.ts`); they are exercised through subprocess tests, `check` and `smoke` instead, and any new logic should live in a loaded, tested module.
- Branch coverage (METRO-50): there is no branch gate for the files Bun runs, because Bun cannot measure branches (the `apps/api` and `apps/web` files moved to Vitest have a 90 percent per-file branch gate, see "What runs where"). Repo-verified with Bun 1.4.4: `bun test --coverage --coverage-reporter=lcov` writes only `TN`, `SF`, `FNF`, `FNH`, `DA`, `LF`, `LH` records, never `BRF`, `BRH` or `BRDA`. Context7-verified: Bun's docs name only `lines` and `functions` as enforced thresholds (`statements` is accepted but not enforced) and say nothing of branches. Web-verified 2026-11-05: branch reporting is an open Bun pull request ([oven-sh/bun#46534](https://github.com/oven-sh/bun/pull/46534)), not released (merge status Unverified beyond that search). `scripts/coverage.test.ts` holds a tripwire that fails when Bun starts emitting branch records; when it does, replace the tripwire with a 90 percent per-file branch threshold in `bunfig.toml` and a failing fixture. Until then, coverage proves a line ran, not that its outcomes were asserted: the lint rules below are the guard against tests that execute code without proving anything.
- Test hygiene lint (METRO-50): `.oxlintrc.json` enables the `jest/*` rules for `*.test.ts(x)`, each with a one-line justification beside it. Oxlint's jest rules recognise only Jest and Vitest imports, so a file importing from `bun:test` is invisible to every `jest/*` rule (Repo-verified on oxlint 1.90.0: the same assertion-free test is flagged without the import and silent with it; upstream request [oxc#23290](https://github.com/oxc-project/oxc/issues/23290), Web-verified). Tests therefore use Bun's injected globals (`test`, `expect`, `describe`, hooks, `jest.spyOn`), typed by `bun-types/test-globals` in `tsconfig.test.json`, and `eslint/no-restricted-imports` rejects `import ... from "bun:test"` so the rules cannot go blind again. `scripts/test-hygiene.test.ts` lints a fixture per rule with the real config and proves the rejection, including an assertion-free test. Enabled: `expect-expect` (with `expectRejection` as an assertion helper), `no-conditional-expect`, `no-standalone-expect`, `valid-expect` (`maxArgs: 2` is a deliberate, documented relaxation: Bun's `expect(value, "message")` accepts a custom failure message, so the second argument is valid; it does not weaken the check, which still rejects a missing matcher or argument), `valid-expect-in-promise`, `require-to-throw-message`, `no-focused-tests`, `no-disabled-tests`, `no-test-prefixes`, `no-commented-out-tests`, `valid-title`, `no-identical-title`, `valid-describe-callback`, `no-export`, `no-done-callback`, `no-duplicate-hooks`, `no-unneeded-async-expect-function`, `no-alias-methods`, `prefer-called-with`. Fix a finding by strengthening the test, never with a disable comment (`reportUnusedDisableDirectives` is on) or by dropping the rule. Vitest files (METRO-77, and the web tests since METRO-79) import `test`, `expect` and the rest from `"vitest"` (globals stay off), which the same `jest/*` rules do see; `scripts/test-hygiene.test.ts` re-runs every fixture above rewritten for Vitest (`vi` for `jest`, imports from `"vitest"`) and proves each rule rejects it, while the Bun fixtures and the `bun:test` import ban stay as they are; `scripts/test-hygiene.test.ts` also fails if a web test file does not import from `"vitest"` or uses `jest.` or `bun:test`.
- Rejected rule sets (METRO-50, measured on this repository at the time): the `pedantic` category (474 findings over 24 rules; 305 are `prefer-readonly-parameter-types` and 55 `no-confusing-void-expression`, none of which finds a weak test) and the `style` category (4920 findings, many contradicting each other or the formatter, such as `sort-keys`, `no-magic-numbers`, `one-var`). Individual rules rejected: `jest/prefer-strict-equal` (170 findings, `toEqual` is deliberate for plain data), `jest/prefer-expect-resolves` (50; Bun's types declare `.resolves` as `void`, which `typescript/await-thenable` rejects), `jest/no-conditional-in-test` (133), `jest/prefer-each` (36), `jest/prefer-ending-with-an-expect` (178), `jest/prefer-expect-assertions` (558), `jest/max-expects` (78), `jest/no-hooks`, `jest/require-hook`, `jest/prefer-lowercase-title` (451), `jest/consistent-test-it` (39) and `jest/padding-around-test-blocks` (formatter territory): noise or style without a weak-test signal. Rules with no findings and no weak-test signal (`prefer-to-be`, `prefer-to-contain`, `prefer-equality-matcher`, `prefer-comparison-matcher`, `prefer-hooks-on-top`) are left off until a case appears. `typescript/require-await` (3 findings, one in production code) and `typescript/prefer-promise-reject-errors` (3, deliberate in tests that reject with a plain value) stay off for the same reason.
- E2E fixtures (`e2e/fixtures.ts`) apply to every test in every project: any console error or uncaught page error fails the test, and any page left open must have zero axe violations. A test that provokes an error on purpose declares it with the `allowedConsoleError` option.
- Failures keep evidence: trace and screenshot on failure and an HTML report in `playwright-report/` (CI uploads both as the `playwright-report` artifact; the lcov file is the `coverage-lcov` artifact).

For bugs reproduce observed failure before a fix; record base revision, expected behavior and smallest relevant source path. Read parity evidence for existing behavior and domain glossary for terms in [feature parity](../product/feature-parity.md) and the [glossary](../product/glossary.md). Add API/UI/security/observability reads only when those boundaries are touched.

Retain settled test seams: deterministic domain/data fixtures, provider/contract boundaries, Workers integration and browser/accessibility journeys when their implementations exist. Cover invalid input, empty data, failed provider and recovery when relevant; use synthetic coordinates, never personal location. A failing regression should prove behavior, not mirror implementation. Do not weaken assertions or skip failures to pass. Record exact checks, fixtures, outcomes and omissions against [quality gates](quality-gates.md). Documentation tasks verify links, routing and scope without claiming app checks ran.

- Component test DOM (METRO-79, replaces METRO-58): the `web` Vitest project runs with `environment: "happy-dom"` (`apps/web/vitest.config.ts`). Vitest gives each test file its own happy-dom window inside its own worker, so no file registers, unregisters or swaps globals, and the Bun-era `dom-test-env.ts` and its test are deleted. Test files import `test`, `expect`, `vi` and the hooks from `"vitest"` (globals stay off) and import React, Testing Library and the code under test statically. Testing Library's automatic cleanup needs a global `afterEach`, so each file calls `cleanup()` itself, and sets `IS_REACT_ACT_ENVIRONMENT` in `beforeAll`. happy-dom's `URL` rejects `file:` URLs, so `headers.test.ts` reads `public/_headers` through `import.meta.dirname` instead of `new URL(..., import.meta.url)`. The project's `sequence.shuffle` comes from `sharedTestOptions` (a project does not inherit the root option): in-file shuffle for the web project is proven in [the METRO-79 evidence](../evidence/metro-79.md).
- Entry files that run on import: `apps/web/src/main.test.tsx` is the one sanctioned exception to "do not load entry files that run on import". `main.tsx` has no testable seam (it only wires `StrictMode`, the boundary and `createRoot` to `#root`), and the ticket requires proving that wiring, so the test creates `#root`, imports `main.tsx` after `vi.resetModules()` and removes the container afterwards; a second test imports it with no `#root` and expects the "Missing application root" error. Keep any logic out of `main.tsx`; put it in a tested module.
- Test runner decision (METRO-74): [ADR-0016](../adr/0016-test-runner.md) accepts Vitest for the API (workerd) and web test projects, with scripts and packages decided later by a stated criterion, on the strength of a [measured spike](../evidence/vitest-spike-2026-11.md) (branch coverage under a per-file gate, workerd for the API, no happy-dom swap). Stage 1 landed with METRO-77 (the API project, see [the evidence](../evidence/metro-77.md)) and stage 2 with METRO-79 (the web project, see [the evidence](../evidence/metro-79.md)); the scripts and packages tests are still on Bun and everything above about them stays in force.
