# Metro Station Finder — engineering handoff

The visual design (Lagoon palette, glass panels, ticket, roundel, tokens) is approved. This folder is how it is delivered.
Everything here is plain static files. There are no inline style attributes, no inline `<style>` or `<script>`, and no CDN. The only network URL is the Google Maps directions link.

## Folder

| Path | What |
|---|---|
| `tokens.css` | All custom properties. `:root` = light, `:root[data-theme="dark"]` = dark, plus a `prefers-color-scheme` block for when `data-theme` is unset. |
| `base.css` | Reset, type, focus ring, selection, scrollbar, and the reduced-motion, reduced-transparency and forced-colours rules. |
| `components.css` | Every component as BEM classes. Colours only come from `var(--…)`. |
| `fonts.css` + `fonts/` | Self-hosted, Latin-subset variable woff2: Hanken Grotesk (400, 500, 600, 650, 700) and JetBrains Mono (500, 600). Licences are OFL 1.1. |
| `icons/` | One 24×24 `currentColor` SVG per icon (paths from Lucide, ISC licence). In the screens, icons are inlined. Decorative ones are `aria-hidden`; meaningful ones sit in a button that has an `aria-label`. |
| `screens/*.html` | One static file per screen and per state, in light and dark. The same file is responsive at 390 × 844 and 1280 × 800. |
| `index.html` | A gallery that shows every file at both sizes (`gallery.css` is for the gallery only). |
| `interactions.md` | How each interactive part behaves. |
| `monorepo/` | Brand assets laid out as `packages/brand`, `apps/web/public` and `apps/mobile/assets`. Every file is generated by `packages/brand/scripts/build-assets.mjs` from `geometry.mjs`: run `npm run build-assets` in `packages/brand` after changing the mark. Font licence files are OFL text and contain the licence's own URLs. |

Load order: `fonts.css → tokens.css → base.css → components.css`.

## Product decisions in this delivery

- **Two inputs on Nearby, given a clear hierarchy (refined).** "Use my location" is the primary action. Below it, **Search for a place** is a labelled slot for Google's `<gmp-place-autocomplete>`. We style only the container: a visible label, a rounded box, and `:focus-within` for the ring. Nothing depends on styling inside the widget's closed shadow root, and Google's popup gets the full panel width. Below that, **Or pick a station** is our own offline combobox over the 16 stations. The two have different labels, so they are never confused. When offline, or when Google fails, the place slot is replaced by a small warning notice and the station picker stays.
- **Visible label matches the accessible name.** Google sets the widget's accessible name to "Search For a Place". Our visible label "Search for a place" contains the same words, which satisfies WCAG 2.5.3 (Label in Name).
- **Map.** The "mock map" label is gone. The map is a real schematic SVG built from the 16 coordinates (see Map below). The prototype's made-up roads and water are dropped, because they weren't real geography. Only abstract planes and a dot grid remain behind the line.
- **English and km/m only.** The Bangla switch, the Bangla names, Noto Sans Bengali and the units switch are removed. See "Later: Bangla" below.
- **Fare ticket.** The MRT/Rapid Pass and 10% stub are removed, and no concession price appears anywhere. **The perforation and stub stay,** but the stub now carries the fare footnote ("Fares as of: DTCA notice dated 8 September 2022; last checked 5 November 2026."), so it has a real job and the approved shape is unchanged.
- **Removed from product screens:** the Design notes panel and button, the "States (dev)" menu, and every placeholder or Demo label. One small "Sample data" tag sits beside fare numbers in the mocks. It has the class `.mock-only` and is not part of any shipped component.
- **Directions.** "Directions in Google Maps" is a secondary link (`target="_blank" rel="noopener noreferrer"`, with a visually hidden "(opens in a new tab)"). It sends only the station's public coordinates as the destination, never the user's position. The primary action on a result is "Route and fare from here". Walk time and distance show as "about … est.".
- **Settings** shows Theme only (System, Light, Dark), plus the fare footnote.

### Visual changes forced by the constraints (smallest possible)
1. **Field outlines** (station combobox, place slot, radio rings) move from a hairline to `--color-ctl-line`, which is 3:1 against the card (WCAG 1.4.11). It's 1px either way; it's just darker.
2. **The ৳ sign isn't in the Latin subset.** It renders from the system font: Nirmala UI or Vrinda on Windows, Kohinoor Bangla or Bangla Sangam on Apple, Noto Sans Bengali on Android. That is consistent enough. If you want zero fallback, the alternative is "BDT 50"; say which.
3. **"→" (U+2192) and "⌘" aren't in the subset either,** so arrows are SVG icons and the shortcut reads "Ctrl K". Show "⌘K" only on Apple platforms, where the system font has it.
4. **The live-line train glide and all pulses** are CSS keyframes and switch off under reduced motion (see interactions.md).

## Breakpoints and layout
- **Below 768px:** full-bleed map, a bottom sheet (`.panel`) and a bottom tab bar (`.tabs`).
- **768px and up:** a floating header pill, a sidebar panel (`--side-w`: 360px, or 400px from 1024px), and the tabs move to the top of the panel. It's the same DOM; only CSS changes.
- **DOM order:** header → nav → main. On phones the nav is drawn at the bottom but comes before the content in focus order, like a site nav.

## z-index scale
`--z-map 0` · `--z-panel 10` (desktop sidebar) · `--z-sheet 20` (mobile sheet) · `--z-tabbar 25` · `--z-header 30` · `--z-toast 50` · `--z-dialog 80` (command palette).

## Map
- **Projection:** equirectangular into a fixed viewBox 710 × 1055. `x = (lng − 90.33) / 0.14 × 710` and `y = (23.89 − lat) / 0.19 × 1055`. The x and y scales differ by cos(23.8°), so the shape is true to life.
- **Layers, bottom to top:** background, planes, dot grid, line shadow (18u), line casing (12u), line (7u, `url(#map-line)` gradient), trip highlight (8u, when a route is set), walk path (2.5u dashed), user pin, station pins, labels.
- **Pin states:**
  - **Default:** 5u, `--color-map-pin` fill with a 2.5u `--color-map-pin-ring`.
  - **Highlighted** (nearest, from, to, detail): 7.5u in `--color-map-label` with a 3u ring and a 15u `--color-accent-soft` halo.
  - **Labels:** highlighted stations and the two termini get a pill label; the rest get a halo label.
  - **User position:** 8u accent with a 3u ring and a pulse, which is off under reduced motion.
  - **Rough-location state:** no user pin and no highlight.
- **Controls:** Zoom in, Zoom out and Show whole line (44px buttons), plus the keyboard keys in interactions.md.
- **Text alternative:** `<title>` and `<desc>` describe the current state, and the Line tab is the full accessible equivalent.

**Failing pairs: 0.** None.

- Hairline borders (`--color-hair`) are decorative separators. They are never the only way to identify a control, so they're exempt from 1.4.11.
- **Blur over the map line:** the glass panel can sit over the dark line, which only darkens the backdrop. All text pairs were checked against the lightest backdrop (map background) in light mode and the darkest in dark mode. Reduced transparency makes the panel solid.

### Focus order per screen
- **All app screens:** Home (logo) → Search stations and actions → Theme → section tabs (4) → sheet handle (mobile: "Make panel smaller", grip, "Make panel larger") → panel content top to bottom → map (one tab stop; arrows pan) → map controls (3) → toast region, if present.
- **Nearby, idle:** Use my location → place widget (Google) → station combobox → Route and fare tile → Line tile.
- **Nearby, result:** Route and fare from here → Station details → Directions in Google Maps → Also nearby (2).
- **Location errors:** the notice action(s) → place widget → station combobox.
- **Route:** From → To → Swap → From handle → To handle → quick picks or ticket → stations on the trip → fare map grid.
- **Line:** direction radio group (arrows switch) → 16 station rows.
- **Station detail:** Back → neighbour stops (2) → Set as origin → Set as destination → Show on map → Directions → fares (15).
- **Palette:** focus moves to the input. Arrows move the active option, Escape closes, and focus returns to the trigger.
- **Lazy failure:** focus moves to the failure container (`tabindex="-1"`), then to "Reload the page".

### Target size
Every interactive element is at least 44 × 44 CSS px, including icon buttons, tabs (52px on mobile, 38px tall × full column width on desktop, inside a 44px-tall group), options, rows and map controls. Small buttons (`.btn--sm`, 36px tall) are always wider than 44px and have 8px of spacing, which meets WCAG 2.5.8. The only exception is the decorative sheet grip line; its button is 72 × 32 and sits in a 32px row with alternative 32px-tall text buttons. **Flagged:** making the handle row 44px adds 12px to the sheet. Recommended.

### Things that rely on colour
- **Route dots:** From is a hollow ring, To is solid. They differ by shape, not just hue.
- **Notice tones:** each has a different icon (info, check, alert, location-off) and words. Colour is never the only signal.
- **Fare map cells:** shaded by fare. The fare is read out in text above the grid and announced in a live region, and the grid is `role="application"` with keyboard reading.
- **Active tab:** `aria-current="page"`, plus a filled pill and a visible label on mobile.
