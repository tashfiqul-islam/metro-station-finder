# Ubuntu onboarding run, November 2026 (METRO-55)

Outcome: the claim "works on Linux" is measured for one environment, not assumed. A newcomer-style run of `mise install`, bootstrap, `hk install`, `bun run check`, build and browser smoke on Ubuntu 26.04 LTS under WSL2 passed, after one prerequisite the documentation did not state: Git 2.54 or newer. Scope is exactly that environment; bare-metal Ubuntu, other releases, other architectures and macOS were not exercised.

## Environment and revision

- **Repo-verified:** revision `8f5b25958ae4d5eca4921981db8d415dc58baaa8` (`origin/feature/metro-rebuild`, merge of PR #65), cloned over HTTPS from the public repository without credentials into a fresh directory in the Linux filesystem (`~/metro55-ubuntu-run/repo`, not `/mnt/*`), then `git checkout` of that SHA. `core.symlinks` default; `CLAUDE.md -> AGENTS.md` materialised as a symlink.
- Host: Windows 11 Pro, WSL2 distro `Ubuntu`, kernel `6.6.114.1-microsoft-standard-WSL2`, Ubuntu 26.04 LTS, x86_64, 20 logical CPUs, about 15.5 GiB RAM.
- Tool versions in the run: mise 2026.11.0 linux-x64; bun 1.4.4; node v26.13.0; hk 2.11.0; pkl 0.32.2; gitleaks 8.30.1; actionlint 1.7.12; zizmor 1.31.1; Git 2.53.0 (distro package) and then Git 2.54.0 (see below).
- The distro already had a user mise and cached tools. To make the run behave like a clean machine, all of mise's data, config, cache and state directories, the Playwright browser directory and the Bun cache were redirected into the throwaway directory (`MISE_DATA_DIR`, `MISE_CONFIG_DIR`, `MISE_CACHE_DIR`, `MISE_STATE_DIR`, `PLAYWRIGHT_BROWSERS_PATH`, `BUN_INSTALL_CACHE_DIR`), and mise itself was installed fresh into the same directory. The user's global mise config was therefore not applied. These overrides are isolation, not part of the onboarding steps.
- Not clean: the distro already had `build-essential`, `libnss3`, `unzip` and `curl`, and no `sudo` or `apt` change was made. Whether a minimal Ubuntu image needs more packages (for example for Playwright's headless shell) is Unverified.

## Failures and workarounds

- **Git older than 2.54.** Ubuntu 26.04 ships Git 2.53.0 (`1:2.53.0-1ubuntu1.1`). `hk install --mise` still succeeds there but installs legacy shim files, and the `hk install` fixture test is skipped with the message "Git ... is older than 2.54". The suite stays green, so the gap is silent unless the skip line is read. Workaround used: a Git 2.54.0 built from source in the throwaway directory. A package route (the Git maintainers' PPA, `ppa:git-core/ppa`, listed on git-scm.com for Ubuntu) would need `sudo` and was not run, so it is Unverified.
- No other failure occurred. No test, assertion or threshold was changed; no code change was needed.
- The Windows `EBUSY` flake in `scripts/tsc-build.test.ts` did not occur on Linux.

## Documentation fixes made

`docs/development.md` now states the verified scope, drops "other platforms were not exercised", adds the `hk install` step and the Git 2.54 prerequisite with the Ubuntu 26.04 finding, and links this record.

## Devcontainer decision

**Decision (owner's delegate): do not add a devcontainer now.** There is no consumer: the owner uses Windows and Ubuntu with mise, and CI already runs on Linux. This run shows mise on Ubuntu reproduces the pinned toolchain from `mise.toml` and `mise.lock` in about 15 seconds of tool downloads plus a 3 second dependency install, so a container adds a second, parallel toolchain definition to maintain (image, features, CI build job) with no failure it would prevent today. Acceptance item 2 (a CI job that builds it) therefore does not apply.

Revisit when any of these holds:

- a contributor needs a reproducible environment and cannot or will not install mise;
- GitHub Codespaces (or another remote development environment) is adopted;
- CI and local runs diverge in a way a pinned image would remove (for example, the runner image changes a tool or system package the checks depend on);
- the Git 2.54 prerequisite or other system packages become a recurring onboarding cost that an image would absorb.

## Cleanup and footprint

The clone and everything inside it (mise installation and data, Bun cache, Playwright browser, the Git 2.54 source and build) were in one directory, `~/metro55-ubuntu-run`, which was deleted at the end. No `apt`, `sudo` or shell profile change was made. Tools still wrote some small user-level caches that existed before and were not removed: `~/.cache/fontconfig`, `~/.cache/aube`, and Bun's own `~/.bun` (modification times only; contents are tool caches). `.env` was never read or touched.

## Unverified

- Bare-metal Ubuntu, other Ubuntu releases, ARM, and Ubuntu with fewer pre-installed packages.
- The Git PPA route for Git 2.54 or newer.
- The explicit-version form `mise exec bun@1.4.4 node@26.13.0 -- bun run check` without a prior plain `mise install`: the run used plain `mise install` before `check`, so whether `check` finds the other pinned tools in the explicit form was not measured.
- Firefox and WebKit smoke projects on Linux (they need `playwright install firefox webkit` and possibly system libraries).
