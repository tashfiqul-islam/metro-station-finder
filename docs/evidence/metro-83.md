# METRO-83: cut the cost of the slowest script test files

Labels: **Repo-verified** (measured in this checkout in the session, numbers below), **Hosted** (read from a GitHub Actions log, run id given), **Unverified** (not measured). Base: `origin/feature/metro-rebuild` at `98f5dd5` (METRO-82 merged, `bun test --parallel=4`). Local machine: Windows 11, 20 logical cores, Bun 1.4.4, Node 26. All local numbers are session measurements (a shell timer around `mise exec -- bun test ...`); raw logs were kept in the session scratchpad and are not committed.

## Why

Under `--parallel=4` the slowest files bound the wall time (see [METRO-82](metro-82.md)). Three files were slow because they spawned the same heavy tool many times for assertions that one run can answer.

## Every assertion that changed

Nothing was removed without a replacement below, but several assertions were merged or replaced. Net `expect()` calls: 4235 before, 4197 after.

`tsc-build.test.ts`

- Three "scripts project rejects ..." tests: before, the output contained `zz-fixture.ts`, contained `TS1294`, and the exit code was non-zero. Now: exactly one output line starts with that fixture's own file, it contains `error TS1294`, and the real exit code of the batch run is non-zero. (The old check could be satisfied by any TS1294 anywhere; this one is per file.) The `-p scripts/tsconfig.json` run became the scripts project inside `tsc -b`; the verdict for that project is the same compiler configuration.
- "checks all nine projects": unchanged assertions, taken from the pristine verbose run (exit 0, nine `Building project` lines) and the pristine `typecheck` exit 0.
- Nine "a type error in <project>" tests: before, exit non-zero, the output contained `<fixture>(1,14): error TS2322`, and 8 assertions that no other project's fixture appeared (72 in total). Now: exit non-zero (batch), the line is present, and the fixture is reported exactly once. The 72 "other fixture absent" checks cannot be kept as written, because every fixture exists in the batch. What they could detect was another project picking up this project's fixture; a second report of the same fixture now detects that. What is lost: the proof that a lone fixture in project A does not make project B fail, which the old assertion only showed indirectly (B had no fixture of its own). Unverified: no mutation covers it.

`types.test.ts`

- "safe program passes": same as before (empty stdout and stderr, exit 0) because the safe fixture has its own `tsc` run. An earlier version of this change derived the exit code from "no own lines", which was circular; that was removed after review.
- "rejects <name>" and "foreign ambient": before, exit non-zero and `TS<code>` anywhere in stdout. Now: the real exit code of the batch run is non-zero, and the fixture's own diagnostic lines match `error TS<code>` (the specific code for index/optional/return/unused, the five foreign codes for foreign ambient, 2304/2868 for DOM no-Bun, 2322 for DOM strict). The exit code is shared by the fixtures of one project, so it alone cannot tell fixtures apart; the own-line check does.
- New: in each safe test, the rejected batch must have no diagnostic that belongs to no fixture (a broken project setup).

`layering.test.ts`

- Rejected scenarios: before, `output` contained the rule name and the exit code was non-zero per scenario. Now: the rule fired on the scenario's own file with severity `error`. The per-scenario exit code is no longer observed; instead the err run on the whole tree must exit with exactly the error count of the json summary, and the two single-scenario tests keep exit code and text. A rule changed to `warn` is caught per scenario (see mutations).
- Allowed scenarios: before, the whole output did not contain `error` and the exit code was 0. Now: no violation of any severity on the scenario's own files, the file must be parsed with at least one dependency, and no violation anywhere in the batch may come from a file that no scenario owns.
- A broken scenario file fails only that scenario's tests, naming the file.

## Parallel safety

All three changed files create their directories with `mkdtemp` (under `.local/` or the system temp directory) and never change the working directory or the environment; shared state is per test-file process and each process makes its own copy or tree. `tsc-build.test.ts` keeps its bounded EBUSY retry when removing the copy.
