# METRO-30 audit: the project against current 2026 standards

Date 2026-11-04. Base `feature/metro-rebuild` at `30a43db`. No code or gate was changed by this audit; its output is this document and the child tickets in module 02 (METRO-31 to METRO-59).

## Method and limits

- Nine read-only research tracks ran in parallel (language and compiler, runtime and platform, quality and testing, supply chain and security, CI/CD and release, observability and accessibility, developer experience, process and AI-driven development, architecture and API). Each had to fetch current sources before judging (Context7, vendor docs, release notes, `npm view`), prefer primary sources, label evidence, and never recommend a beta or release candidate.
- The researchers' reports were treated as leads. I verified the highest-impact claims myself (table below) and corrected or dropped the ones that failed.
- Evidence labels: **Repo-verified** (read or run in this repository), **Context7-verified**, **Web-verified** (primary page fetched on 2026-11-04), **Secondary** (search summary or third-party article, a lead only), **Unknown** (could not be checked).
- Not checked, by design or access: live GitHub settings (rulesets, environment policy, secret scanning, CodeQL, immutable releases, repository visibility and plan; no API access), Cursor itself, CI run durations, Renovate's live behaviour.
- Latest means latest **stable**. Betas and release candidates appear only under Watch with the stable condition.

## Summary

- Nine areas were audited, with the rows listed below (a row can span several researcher findings). Findings that need action became 29 new tickets (METRO-31 to METRO-59, all in module 02, Backlog); 21 of them carry the needs-decision label (counted from Plane). A ticket does not always mean a defect: some Watch or Unknown rows have a ticket because the next step is a decision or a measurement (for example SC-03, RT-14, QT-03, QT-23). Rows with no ticket are Keep, Watch or Unknown. P1 means the highest priority I set: a security or safety exposure, a deadline, or a foundation other work depends on.
- Highest priority (P1 tickets): security headers and CSP (31), legacy Maps key (32), Cloudflare token expiry before 2026-12-03 (33), default-branch plan and tag policy (34), randomized test order (35), independent-review definition (36), untrusted-input policy (37), agent authorization controls (38), Maps and geolocation design (39), station domain model (40), WCAG 2.2 AA (41), production deploy (57).
- Things already current and verified: TypeScript 7.0.2 compiler, `strict`-family flags beyond the TS 7 defaults, solution-style root (the official create-vite pattern), Valibot 1.5.0, Hono 4.13.x, Vite 8.3.5, React 19.3.1 with the React Compiler 1.0 setup, Node 26 (LTS) and Bun 1.4.4 pins, the Static Assets SPA config, workflow permissions and SHA pinning, the aggregate `Quality gates` job, per-file coverage plus the scope gate, the structured allow-listed log line, gitleaks 8.30.1.

## Watch list, with the stable condition for each

- TypeScript 7.1 and its API: adopt only when stable, past the 3-day cooldown, and `boundaries.ts` plus dependency-cruiser are proven (then a small ticket retires `@typescript/typescript6`).
- Workers Tracing and OTLP: when generally available.
- `wrangler preview`: when Cloudflare calls it generally available and the open bugs are fixed.
- `@cloudflare/vite-plugin` 2.0, Hono 5: when stable.
- oxlint JS plugins and `typeCheck`; oxfmt 1.0: when stable and proven against the full check.
- Stryker with Bun: when an official or verified runner exists.
- Bun `--parallel` and `--shard`: only after they are shown compatible with the per-file coverage gate and the scope gate.
- Merge queue: when more than one contributor opens PRs at once.
- Workflow lockfiles: when Renovate supports them.
- Cursor with the TypeScript Native Preview extension: confirm in a real window.
