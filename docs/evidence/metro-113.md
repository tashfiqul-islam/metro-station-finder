## Decisions and deviations

- Single current result: `Nearby` holds one value, `pick` or `location`. A pick replaces a location result (its heading, ticket and highlight go; the result section is unmounted) and a location result replaces a pick (`StationPicker current` false hides its ticket). The map highlight follows the current result only; the user pin is drawn only for a device fix (a searched place is not where the user is, so it gets the highlight and no pin). A rough fix clears a location result and leaves a pick as the current result (the user asked for nothing new). Focus: the result heading after a result (every new result mounts a new heading, so the same station again also takes focus), the first notice action after an error. Sheet: locating, a result and an error go to half; a late outcome while the user types in the search box moves neither focus nor the sheet. Tests for both orders: `Nearby.test.tsx` and `e2e/location.e2e.ts`.
- A device fix asks for no walking route: the route area is absent, not an error (tests with Maps unavailable and with a working route service prove no call). A searched place keeps the walking route it had (Places and Routes belong to METRO-114); it uses the same result view with the walking row. This is a decision, not from the ticket: removing the route from searched places would have taken a working behaviour away in a slice that is about not touching Google.
- The destination select and its per-trip fare of METRO-88 are gone from the location result: the ticket specifies the fare range with the production footnote for a good fix, and the trip fare belongs to the Route tab of the handoff, which has no screen yet. Tests that covered the select (destination list, forgotten destination, unknown trip fare, fare currency) were removed with it; the fare range, its footnote and the no-fare case have new tests.
- Notices: denied, unavailable and rough are a labelled group (`role="group"`, named by the message) with their actions, and focus goes to the first action (the notice itself when it has none, for denied with Maps unavailable). They are not also `role="alert"`: the handoff says role alert only for notices that appear without moving focus (`interactions.md`, Use my location, item 4). A late outcome while the user types keeps `role="alert"` and takes no focus. The METRO-88 e2e that asserted `alert` plus `toBeFocused` for denied was changed for this reason.
- "Try again" unmounts the notice that held focus, so focus moves to the stable "Use my location" button (only when focus was inside the notice). That button uses `aria-disabled` while locating, not `disabled`, so it keeps focus and its place in the order.
- Handoff order: Use my location (primary), its consent line, then Search for a place, then Or pick a station, then the one result. The handoff's result screen has no search fields; the controls stay here so a user can start a new search without leaving the result. The notice sits above the button; the button and consent line stay visible while a notice shows (the handoff replaces them), so the primary action is never missing.
- Locating: one polite `output` (implicit status) with the mark, "Finding your position" and "This can take a few seconds indoors." (handoff). It sits under the button so it is in view at half. The mark loops through `mark-searching.css` (reduced motion shows it still, tested). The status holds no control.
- The 8 s timeout replaces ADR-0009's 10 s (the handoff's value); `maximumAge: 0` and `enableHighAccuracy: false` are unchanged. `getCurrentPosition` and the `navigator.geolocation` getter are guarded (some restricted contexts throw), and each guard has a test. Context7 (MDN) confirms the three `PositionOptions` and the three error codes; whether the browser excludes the permission-prompt time from `timeout` is Unverified. ADR-0009 and the slice specification carry a short METRO-113 note.
- Estimates: "about" + `formatEstimate` + "straight-line distance · est." (tens of metres under 1 km, one decimal of km above) and the same for Also nearby ("about 1.1 km · est."). The straight-line distance of the old result (two decimals, no "about") is replaced.
- "Also nearby" lists the two next-nearest stations by distance, as static cards (not links: there is no Station screen). The handoff's neighbour strip on the line ("Position on the line") is not built; the ticket does not list it.
- The position never leaves the device: `e2e/location.e2e.ts` attaches its request listener before the page loads, presses the button after the first load settled and asserts that nothing is added except our own web-vitals report (LCP is final at the first input; its keys are checked and it carries no position) and the same-origin font file the result's eyebrow draws with; every request ever seen is same-origin or the stubbed Google script, none carries a coordinate, the Maps stub recorded no `fetchFields` and no route, and nothing was blocked. The check is not vacuous: it first failed on the web-vitals report, which is how that allowance was found. `Nearby.test.tsx` adds a unit-level check on `fetch` and the console.
- The `e2e` changes that are not new tests: `maps-stub.ts` `stubGeolocation` takes `"unavailable"` and `"pending"` (and an accuracy of -1 for none: JSON carries no NaN into the page); `station-picker.e2e.ts` waits only for finite animations before its axe scans, because the primary button's decorative ping loops forever (a wait on every animation never ended), and an `afterEach` in that file and in `location.e2e.ts` waits for the finite animations before the fixture's end-of-test axe scan (Firefox twice measured the open popup's options mid-fade, `color-contrast` 2.9 and 1.24 on `option` text, in a test that ends right after the popup opens; the race was already in the file and the wait observes state, it removes no assertion); `nearest-station.e2e.ts` follows the new result (no destination select, a fare range, the notice group, the new region order and its ARIA snapshot, a Tab count that adds only the Directions link where links are tabbable).
- Contrast: no token was added, so the 53 pairs of `scripts/design-contrast.ts` are unchanged and green (`bun run check`). axe is clean in light and dark at 390 and 1280 px for locating, denied, unavailable, rough, rough-unknown and the result (`location.e2e.ts`), on every project in CI mode.
- Offline: no user-visible string claims offline use (METRO-106); the built-output test of METRO-112 still passes.
- Deleted code: the old `Slice` result block, the destination state and the route hook inside `NearestStation.tsx` (the hook moved to `walking-route.ts`).
