# ADR-0024: A small hand-written service worker keeps the app shell offline

- Status: Accepted
- Date: 2026-11-09
- Ticket and specification: METRO-106 (Plane); no separate specification, the ticket and its owner decision of 2026-11-08 (add a small service worker rather than drop the claim) are the contract.

## Context

The manifest, the design's offline state and the share image say the app works offline. Station search by name, the SVG line map, fares and the line list are local data and code ([ADR-0018](0018-where-core-runs.md), [ADR-0022](0022-nearby-screen-one-lazy-boundary.md)), so only the files need to be on the device. Until this ticket nothing stored them, and tests forbade the word "offline" in shipped scripts ([METRO-112](../evidence/metro-112.md), [METRO-114](../evidence/metro-114.md)).

Constraints: no new dependency; the first-visit JS limit and the per-screen and shared lazy limits of [ADR-0023](0023-bundle-budget-model.md) (the worker needs a place in that model); the CSP is unchanged ([ADR-0011](0011-security-headers.md)); Workers Static Assets serves the files through `run_worker_first` for `/api/*` and `/assets/*`; the position goes to Google only ([ADR-0009](0009-maps-provider-design.md)).

Facts the design rests on, with their sources:

- Context7-verified (Playwright docs): `page.route` and `context.route` do not see requests a service worker handles and are not applied to fetches the worker starts; the docs recommend `serviceWorkers: "block"` for interception tests.
- Web-verified (MDN, Using Service Workers): a successfully installed new worker waits while the old one controls pages; it may call `skipWaiting()` to take over open pages; a rejected install promise means the worker does nothing; `clients.claim()` adopts open pages. MDN, `ServiceWorkerRegistration.update()`: the script fetch bypasses the browser caches if the previous fetch was over 24 hours ago.
- Web-verified (Cloudflare docs): with `not_found_handling = "single-page-application"` a request that matches no asset gets `index.html` with 200; the implicit `Sec-Fetch-Mode: navigate` detection is off once `run_worker_first` is an array of patterns; static assets get `Cache-Control: public, max-age=0, must-revalidate` and an ETag by default.
- Repo-verified: `/_headers` gives `/assets/*` the immutable header and everything the app CSP; `scripts/bundle-budget.ts` fails on a built JS file the Vite manifest does not list.

## Decision

We will ship one classic worker, `/sw.js`, written by hand in `apps/web/src/sw/` with its logic in `worker.ts` (cache, network and clock injected) and built by `scripts/sw-plugin.ts` after the client build.

- Precache. At build the plugin lists `dist/client` (the page as `/`, every hashed file, `icons/icon-192.png`, `apple-touch-icon.png`, the manifest and `theme-boot.js`; never `.vite/`, `_headers`, `robots.txt`, `licenses.txt`, source maps, `sw.js` itself, `favicon.ico` or the large, maskable and monochrome PNG icons, which only an install prompt reads, online), fails the build unless every file Vite's manifest names is in that list, and hashes the paths and bytes of the files and of the worker's own bundle (and the kill flag) into a 12 hex digit version, so a release that changes only the worker logic gets a new cache name. With Data Saver on (`navigator.connection.saveData`) the install fetches nothing: the app works online and offline use waits for a visit without it. The cache is `metro-shell-<version>`. Install fetches each file (hashed files may come from the HTTP cache, the others with `cache: "reload"`) and requires a plain 200, HTML only for `/`; any failure rejects the install, so the old worker and its cache stay, and deletes this version's cache only if the install created it (a cache of that name that already existed belongs to a live worker and is kept). Every cache gets a marker with its install time. `favicon.ico` is left out because a script `fetch("/favicon.ico")` fails in Playwright Chromium: the same fetch fails against a plain Node server, while `/favicon.ico?x=1` and any other name succeed, and the Worker, `_headers`, the CSP, `nosniff` and the content type are not involved (Repo-verified; the browser-side cause is Unverified). The page also declares `favicon.svg` and `apple-touch-icon.png`.
- Fetch. Only a same-origin GET is touched. `/api/*`, `/sw.js` and every other origin (Google, fonts) get no `respondWith`, so they never enter the worker's logic or any cache. A navigation to a page path (no file extension) is network first: a network error, a 5xx or no answer within 3 s serves the cached page of this version, or of the kept older one, if there is one; so a slow network can show a cached page. A navigation to a file path (`/robots.txt`, `/licenses.txt`) is never answered with the page. The network answer is never written to the cache, because a newer page stored under older assets could not work offline. Files under `/assets/` are cache first, looked up in this version's cache and then the kept older one; a miss is stored only if it is a plain, unredirected, same-origin 200 that is not HTML, and a failed store (full storage) never fails the answer. The unhashed precached files (`theme-boot.js`, the manifest, the icons) are network first, so a newer page never runs next to an older copy of them. A cache that was evicted is not recreated by a fetch. A key is a path without its query string and the shell key is the fixed `/`, so a position or a place name in a URL can never be stored.
- Update. A new worker installs into its own cache and then waits. It does not call `skipWaiting` by itself, because a deploy removes the old hashed files from the server, and an open page that lost its cache could not load its next lazy chunk. The page shows the toast "A new version is ready." with Reload and Dismiss, inside the shell's toast region, in a `role="status"` element mounted empty first. The prompt is offered only for an update: the page decides that when it finds the new worker, from `registration.active` being set. It does not use `navigator.serviceWorker.controller`, because a first install claims the page and WebKit reported the worker as installed after that claim, which showed a false "new version" prompt on a first visit (Repo-verified in the e2e run, fixed with a test). Reload sends the single message `skip-waiting` to the registration's waiting worker; the new worker activates, claims the page and deletes every `metro-shell-` cache except its own and the newest older one (the previous version stays, for tabs still running it), and the page reloads once on `controllerchange` (only after that press, not when the first install claims the page). While it waits the prompt says "Updating…" in the same polite status and focus moves to Dismiss, because the Reload button is hidden. If the takeover has not happened in 5 s the prompt says so in fixed words. Dismiss leaves the new worker waiting: it takes over when no page uses the old one, which the browser does on the next visit. A dismissed prompt is not offered again in that page view. A shown page also asks for a newer worker whenever it becomes visible while online (`registration.update()`), and the worker is registered with `updateViaCache: "none"`. The registration's waiting worker is told, not the object seen at install: in WebKit the older reference did not deliver the message (Repo-verified, cause Unverified).
- Registration. `startServiceWorker()` in the entry is a few lines: in production builds it waits for load and idle, then imports `register.ts` as a lazy chunk. The first visit downloads and runs none of it; `sw.js` and the precache requests come after load. While `navigator.onLine` is false the registration waits for the `online` event, so a page opened without a network still learns of updates later. Failures are dropped without a log.
- Served correctly. `/sw.js` is answered worker-first by the same route as `/assets/*` (`apps/api/src/app.ts`, `run_worker_first` gains `"/sw.js"`): a present file passes through with the static-asset default `max-age=0, must-revalidate` (not immutable), JavaScript MIME type and the app CSP; if it were ever missing the SPA fallback's `index.html` becomes a no-store 404 envelope, so a browser never reads HTML as a worker. Scope is `/`, the script's own directory, so no `Service-Worker-Allowed` header is needed. `_headers` and the CSP are unchanged: `script-src 'self'` covers the worker and `connect-src 'self'` its fetches.
- Offline behaviour. Station picker, map, fares and the line list run from the cached files. The place-search notice (`navigator.onLine` false) uses the handoff's sentence. The web-vitals beacon is skipped when `navigator.onLine` is false (the sample is dropped, not queued).
- Claims. The offline sentences exist in two places only: the notice in the Nearby chunk and one sentence of the manifest description ("Stations and fares work offline."). Tests pin both places, and fail without the worker in the build. The share image and the install screenshots are not shipped (see the evidence).
- Kill switch. `METRO_SW_KILL=1 bun run build` writes a `sw.js` with no fetch handler that skips waiting, deletes every `metro-shell-` cache, and unregisters itself. It does not reload open pages: every page registers `/sw.js` after load, so a reload would loop for as long as the kill build is deployed; the open page keeps working and the next load has no worker, and registers the kill worker again, which does the same quietly. Its version differs from the normal build's (the kill flag is hashed), so a following normal build reuses no cache name. Because browsers check `sw.js` on navigation and the file is never immutable, deploying it removes a bad worker from every device that visits; the next normal build, which registers a worker again, ships after it. A missing or HTML `sw.js` does not remove an installed worker, which is why the file must stay present (the route above makes its absence loud).

## Consequences

- Easier: the shell opens with no network; a deploy reaches online users on their next visit and installed apps on the next time they are shown; a broken worker has a documented way out.
- Harder: every first visit, and every update, downloads the whole shell in the background after load and idle: 17 files, 482,508 bytes raw, about 231,000 bytes gzipped (the two fonts, 75 KB, do not shrink; the large, maskable and monochrome icons were taken out of the list, from 730,507 raw); Data Saver skips it; the worker (3.8 KB) and the registration chunk (2.2 KB) are lazy and fit their buckets.
- The first-visit JS grew by 164 raw and 68 gzip bytes (the entry's start function and the beacon guard): 235,584 / 74,227 against 250,000 / 80,000; first-visit CSS is unchanged. The gate's `dynamicImports` rule keeps the registration chunk out of it. This ADR amends the bundle model of ADR-0023 by two additions and no change to a limit: the registration chunk (`src/sw/register.ts`) is a shared lazy root (shared lazy now 20,435 raw / 9,179 gzip of 27,000 / 12,000), and `sw.js` is a fifth bucket, `WORKER_SCRIPTS`, an exact-name file from outside the manifest, never first-visit, with its own limit of 6,000 raw / 2,800 gzip (measured 3,824 / 1,730), a printed line labelled `worker`, and a fail-closed check: if a built chunk makes the call `register("/sw.js"` and the build has no `sw.js`, the gate fails with one fixed message. A stray `sw2.js` is still an orphan.
- A page open during a deploy keeps running the old version until Reload or the next visit; the prompt can be dismissed, so a very long-lived tab can stay old. A navigation is current whenever the network answers within 3 s without a 5xx; on a slow network or a server error it can show the cached page of the installed version.
- Other tabs. After Reload in one tab, a second tab still runs the old page under the new worker. The previous version's cache stays until the next activation, so that tab's lazy files still resolve, and the tab hears `controllerchange` and gets the same prompt, whose Reload only reloads. Two versions back is not kept: a tab older than that, or a tab that stays open through two deploys, can fail to load a lazy chunk and shows the lazy-load failure text with its reload button ([ADR-0020](0020-first-visit-budget-and-lazy-features.md)). to a page a worker controls in every browser: with the worker allowed, WebKit let the real Maps script through during development of the e2e spec (Repo-verified, two runs; see the evidence). The project default is `serviceWorkers: "block"`, and the specs that allow the worker mark their pages with `workerMayControl`, after which the place-search helpers that trigger the Google loader throw; the offline spec also fails on any request leaving the machine.
- A trailing-slash `/sw.js/` is a page path to the Worker and gets the single-page app, as any unknown path; it is not the worker file and a browser never registers it.
- Playwright route stubs do not apply to a page a worker controls in every browser: with the worker allowed, WebKit let the real Maps script through during development of the e2e spec (Repo-verified, two runs; see the evidence). The project default is `serviceWorkers: "block"`, and the specs that allow the worker mark their pages with `workerMayControl`, after which the place-search helpers that trigger the Google loader throw; the offline spec also fails on any request leaving the machine.
- Takeover race seen only under automation (Unverified in real browsers). When a request reaches the old worker while Chromium is stopping it for the takeover, the old worker is restarted and the waiting one stays waiting; the page then shows the fixed failure words after 5 s and stays usable, and the next visit applies the update. Measured with 12 parallel Playwright workers on a loaded machine: about one Reload press in four failed to take over while the page was still loading, none of 32 once the page had settled and the workers were stopped first, about 1 in 100 with that stabiliser in the Reload tests. The restarted worker also hung page requests there, which points at the test tool's debugger attach, not at the worker script, but no real-browser run exists. The suite settles the page and stops the idle workers before a Reload press (`stopWorkers` in `e2e/offline-shell.e2e.ts`); an automatic reload as a fallback was tried and removed because the navigation hung too. Related tool limit: `context.setOffline` hangs on a stopped worker in Playwright 1.64.1, so "open offline after the browser stopped the worker" (a phone's normal case) is covered only by the owner phone check.
- Firefox: `setOffline` fails navigations with `NS_ERROR_OFFLINE` before the worker can answer, so the two real-server tests that use it skip Firefox with a recorded reason; the static-server group covers Firefox by stopping the server.
- Unverified: behaviour on real iOS Safari and Android Chrome installs (storage eviction, update timing), the effect of the background precache on a slow mobile connection, `favicon.ico` fetch failure outside Playwright.
- Revisit on a Vite, Workers Static Assets or `@cloudflare/vite-plugin` upgrade (the plugin reads `dist/client` after `writeBundle`), or when a second screen or route is added (the page cached for navigations is the single screen).

## Alternatives considered

- Workbox or `vite-plugin-pwa`: rejected, a new dependency and a larger worker for a four-strategy cache; the owner asked for a small hand-written one.
- Calling `skipWaiting` on install: rejected, it can strand an open page without the files its next lazy import needs, and it hides a half-applied update.
- Updating the cached page from every network answer ("stale while revalidate"): rejected, the cached page could then name assets the cache lacks.
- Reloading automatically when the new worker takes over: rejected, it can discard what the person typed or picked; the prompt asks first.
- Precaching from the registration page (a list fetched at run time): rejected, the list must be the build's own record, checked against the manifest at build time.
- Serving `/sw.js` through `_headers` rules for `Cache-Control`: not needed, the static default already revalidates, and the owner's rule is to leave `_headers` alone.
- A `Service-Worker-Allowed` header: not needed, the script is at the scope root.

## Confirmation

- `apps/web/src/sw/worker.test.ts`, `register.test.ts`, `start.test.ts`, `sw.test.ts` (Vitest, per-file thresholds): routing (API, Google, other methods, the worker itself and file paths untouched), install failure on a 404 or an HTML answer, a failed install of the SAME version leaving the live cache whole, Data Saver, retention of the newest older cache, a full cache (rejecting `put`) still answering, an evicted cache not recreated, network first with the 3 s wait and the kept older cache as fallback, the kill switch, the message check, a scope whose `fetch` must be called as a method, the prompt, focus moving to Dismiss with "Updating…", the 5 s failure text, a second tab hearing the takeover, and registration waiting for `online`.
- `scripts/sw-plugin.test.ts` (Bun, 100 percent): the shell list and the excluded icons, the manifest cross-check that fails the build, a version that changes with the worker's bytes and with the kill flag. `scripts/bundle-budget.test.ts`: the worker bucket (label, own line, limit at the byte, orphans, fail-closed on a registered but absent worker, from disk too) and the registration chunk as a shared root.
- `apps/api/src/assets-route.test.ts`, `index.test.ts`: `/sw.js` passes through, a missing one is a no-store 404, only GET and HEAD.
- `e2e/offline-shell.e2e.ts` (four browsers): no worker request and no registration chunk before load; offline reload, picker, map, fares, line list, deep link without a stored query, a file path not answered with the page; a 200 from `/api/*` never cached or answered offline; update, Reload by keyboard, Dismiss, only the previous cache kept after a third deploy, two tabs, a worker that cannot take over (focus, "Updating…", axe), a removed file still served, an install that fails, the kill-switch build removing a live worker; no request leaves the machine. `e2e/web-vitals-lab.e2e.ts` runs with the worker allowed. `e2e/station-picker.e2e.ts` pins where the word "offline" may appear in the build and requires `sw.js` and its registration. `scripts/brand-assets.test.ts`, `scripts/build-brand-assets.test.ts`: the manifest sentence.
- Mutation checks run for this ADR (restored after): a cache-first route for `/api/*`, registration without the scheduler, no cached page fallback, no retained cache, a version that ignores the worker bytes. Each made the named tests fail.
