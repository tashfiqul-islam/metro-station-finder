# ADR-0021: Style with plain CSS and design tokens, load the landing slice lazily

- Status: Proposed (the owner accepts by merging; the lazy landing slice below amends ADR-0020 and needs that review)
- Date: 2026-11-08
- Ticket and specification: METRO-105 (Plane); the ticket description and the owner decisions of 2026-11-08 are the contract. The owner-approved design handoff (Lagoon palette, glass panels, light and dark) is the visual source of truth. It is an untracked folder and is never committed; what it contained is now in the repository files named below.

> Amendment 2026-11-10 (METRO-119): the pre-paint theme script also sets the two `theme-color` tags in `index.html` (each carries `data-scheme` and `data-system`) to the chosen theme's page background colour, and the theme button does the same through `syncThemeColor`. System leaves each tag to its `prefers-color-scheme` query. It extends the decision below and does not reverse it: the script stays one external file under 600 bytes, with no inline script or style and no CSP change. See [brand](../product/brand.md).

> Amendment 2026-11-11 (METRO-117, decision unchanged): `components/common.css`, `nearby.css` and `route.css` are split by component (`typography`, `button`, `roundel`, `notice`, `empty`, `status`, `toast`, `result`, `ticket` and others), each imported by the module that draws it; `fonts-mono.css` is imported by the component files that set `--font-mono`. `Icon` draws one export of a per-icon module in `icons/shapes/` (31 modules; `icons/icon-data.ts` no longer exists). Where the text below names the old files or the 31 named exports of `icon-data.ts`, read these. It extends the decision below and does not reverse it. See [brand](../product/brand.md).

## Context

The design handoff delivers plain static files: `tokens.css`, `base.css`, `components.css` (67 KB), `fonts.css` with two Latin variable woff2 fonts, 31 Lucide icons, `theme-boot.js`, and screens in light and dark. Every product slice (METRO-15) builds on it, so the foundation must be settled once.

- Repo-verified (ADR-0011, `apps/web/public/_headers`): the CSP is enforced with no inline style or script of our own: `script-src 'self'` plus two Google hosts, `style-src 'self'` plus Google's font host and two hashes. Dynamic values may only go through CSSOM `setProperty` or data attributes.
- Repo-verified (ADR-0020): the first visit is limited to 250,000 raw / 80,000 gzip bytes of JS and CSS, measured from the Vite manifest. Before this change it was 242,839 / 77,186, headroom 7,161 / 2,814.
- Context7-verified (Vite 8.3.5): CSS imported from JS is extracted and hashed; CSS imported in an async chunk becomes a chunk of its own and loads with it (`build.cssCodeSplit`); a font referenced by `url()` in CSS is a hashed asset (inlined only below `assetsInlineLimit`, 4 KB by default, far under these files); files in `public/` are copied as they are and referenced by a root path.
- Repo-verified (this build): Vite leaves a classic `<script src>` in `index.html` alone and copies it from `public/`; it rewrites `<link rel="preload" href>` to the hashed asset; the CSS of the entry chunk is one linked stylesheet.
- Web-verified (MDN, 2026-11-08): `document.startViewTransition` is Baseline 2025 (newly available); `prefers-reduced-transparency` has limited availability. Repo-verified: Playwright 1.64.1 `emulateMedia` has no reduced-transparency option.
- Web-verified (Lucide LICENSE): ISC, with a few icons also under Feather's MIT licence; both texts and the two SIL OFL 1.1 font licences are in `apps/web/public/licenses.txt`.
- Measured (Repo-verified, two separate builds, same sources): with the slice imported statically into the entry, the first visit is 277,620 / 86,488, over the budget by 27,620 / 6,488 bytes. With the slice lazy (shipped) the first visit is 249,338 / 78,021 (248,109 / 77,397 before the review fixes to the shell), and the sum of all files is 293,404 / 93,618. The two builds differ in total (277,620 first-visit against 288,211 all files) because a lazy split adds chunk and preload-helper overhead and a second copy of shared helpers, which the static build does not pay; the static figure is the one that decides whether the slice fits the entry.

## Decision

We will style with plain CSS and custom-property tokens, with no new dependency, in `apps/web/src/styles/`.

- Order (the design's, enforced): fonts, then tokens, then base, then components. `styles/index.css` imports `fonts.css`, `tokens.css`, `base.css` and `components/shell.css`, and `main.tsx` imports it first, so it is the first rules in the one entry stylesheet. A screen or component imports the component files it uses (`components/common.css`, `fields.css`, `nearby.css`, `route.css`, `line.css`, `settings.css`, `station.css`, `palette.css`, `map.css`, `nav.css`, `brand.css`, `header-extras.css`), so they load with its chunk and stay out of the first visit. Colours, radii, shadows, motion, layers and layout sizes live only in the `tokens*.css` files. Light is `:root`, dark is `:root[data-theme="dark"]` and, with no `data-theme`, a `prefers-color-scheme` block with the same values.
- Themes: System, Light, Dark, saved as `localStorage["msf-theme"]` (`src/theme/theme.ts`, every access in `try`/`catch`). `public/theme-boot.js` applies it before first paint as a classic, same-origin script in `<head>` with no `defer`, so the CSP is unchanged. The header button (`ThemeToggle`) cycles the three values and reveals the change with a View Transition circle where the API exists (feature-detected, skipped under reduced motion, instant otherwise).
- Fonts: Hanken Grotesk and JetBrains Mono, Latin variable woff2, `font-display: swap`, hashed under `/assets/` (immutable cache). Only Hanken Grotesk is preloaded; JetBrains Mono is fetched only when text uses it. The taka sign is not in the subset and falls back to a system font; the `Price` component hides the visible sign from screen readers and speaks "N taka".
- Icons: `Icon` draws one of 31 named exports of `icons/icon-data.ts` (Lucide) as inline SVG with `currentColor`, `aria-hidden` by default, so a build bundles only the icons it imports.
- Layout shell: `AppShell` renders header (brand slot, action slot, theme button), an optional section nav (`SectionNav`, links with `aria-current="page"`, never tabs), one `main` panel, a map slot and a notifications region, in that order. The panel is a bottom sheet below 768 px and a sidebar from 768 px. Drag writes `--sheet-h` with `style.setProperty` and sets `data-dragging`; release removes both, deletes the empty `style` attribute and sets `data-snap`. The handle row is 44 px (owner decision; the handoff drew 32 px). Slices set the snap through `useSheet()`.
- The nearest-station slice adopts tokens and classes with its copy, roles, ARIA and keyboard order unchanged. The shell's own `main` replaces the slice's, so there is one landmark. The shell adds the theme button before the slice in tab order, and on phones the three handle controls.
- Budget (amends ADR-0020, which kept the landing slice in the entry chunk): the landing slice and the Maps adapter load as one lazy chunk through `lazyFeature`. Entry CSS and JS hold the shell, tokens, base and theme code. Measured first visit: 249,338 / 78,021 including `theme-boot.js`. No limit was changed. `lazyFeature` now passes a loaded feature's own render error to the root error boundary instead of showing "could not be loaded" (only a rejected loader is a load failure). Such an error is reported exactly once, as `Render error: <name>`, by the root callback (pinned by a test).
- Sheet focus and snaps: the shell has one slice-agnostic rule: when keyboard focus enters the panel content while the sheet is at peek, it opens to half, so a keyboard user is never left in a clipped control (focus on the handle's own controls does not open it). Every other snap rule is a slice rule and stays with the METRO-15 slices, which call `useSheet().setSnap`: typing in search to full, a result or an error to half, "Show on map" to peek, opening a tab from peek to half. A drag follows one pointer; a second pointer, a cancelled or lost capture, and an unmount restore the sheet without changing the snap. Each snap change is announced as "Panel <height>" in a polite status text.
- Header brand: `Brand` draws the Nearest mark on its gradient tile and the wordmark as the Home link (`href="/"`, accessible name "Metro Station Finder, home", which holds the visible text on phones, where only "Metro" shows, and from 768 px, where the full name shows; a real space separates the two words for axe's label-in-name rule). The mark is inline SVG so its line, station and ping animate in CSS on every load with the handoff timings (draw 560 ms in-out after 120 ms, pop 440 ms spring after 420 ms, ping 560 ms out after 680 ms) and stay still under reduced motion; colours are classes over tokens. The SVG body is a constant string. The looping ping for the locating status is in `components/mark-searching.css`, not in the entry. The header slot `brand` replaces it.
- Sheet room: the panel reserved 84 px under it for a tab bar that is not drawn yet, so the sheet floated above the screen bottom. The reserve is now a token, `--sheet-reserve`, 84 px with a section nav and 8 px (the side gap) without; `AppShell` adds the class `app--plain` when no `nav` is passed. A class was chosen over a `:has()` selector because `:has()` needs Firefox 121 and the handoff floor is Firefox 113; a class has no floor. `--sheet-full` is replaced by `--sheet-top` (64 px) and the reserve, computed on `.app` where the override applies, so full height keeps its top edge 64 px below the screen top either way. The map frame and the toast region use the reserve too, and the drag clamp in `sheet.ts` knows both insets. `scroll-padding-bottom` stays 96 px: the tab bar sits under the panel, not over its content.
- Entry budget after the brand: the logo cost about 4.7 KB raw, against 1,050 bytes of headroom, so room was made without changing a limit or the logo: the notice, toast and inverse colours, the map colours, and the ticket, tab, toast, scrim, thumb and veil values moved out of `tokens.css` into `tokens-parts.css` and `tokens-map.css`, imported by the component files that use them (so they load with the slice); the JetBrains Mono `@font-face` moved to `fonts-mono.css`, imported by `common.css`; the five theme-card preview and ticket-mask tokens (the same in both themes) moved to `tokens-parts.css` too (a first version dropped them as unused and broke the ticket notches, because the use is in `route.css` and `settings.css`; `checkTokenUse` in `scripts/css-rules.ts` now fails on any `var()` with no declaration, and on a component that uses a lazy token without importing its file); `revealTheme` moved to its own module that the theme button loads with `import()` on the first press that can use it (without the API, or under reduced motion, the change is immediate and nothing is fetched; a failed load still changes the theme); `theme-boot.js` lost its comment. Cost: the first press of the theme button with View Transitions fetches a 656-byte chunk first. The contrast test merges the token files.
- Reduced transparency: the override in `tokens.css` names every theme selector (`:root`, `:root[data-theme="dark"]`, `:root:not([data-theme])`) and is last in the file, because the dark selectors are more specific than a bare `:root` and a plain `:root` override left the dark panel translucent (found in review).
- Gate accounting: `scripts/bundle-budget.ts` counts the public head script `theme-boot.js` as first-visit and no longer reports it as an orphan; a build without it is unchanged. It adds bytes to the first-visit total and loosens nothing.
- Lint: `import/no-unassigned-import` allows `**/*.css` only, the one side-effect import a Vite app needs.
- Rules as tests: contrast of the handoff's 53 pairs in both themes; no inline style, no colour literal outside `tokens.css`, load order.

### Deviations from the handoff

- Handle row 44 px, not 32 px (owner decision).
- `components.css` is split into the files above (same rules); the patterns-sheet and `.mock-only` rules are dropped as not part of the app.
- `base.css` also keeps the forced ring of the earlier `focus.css` for the two error fallbacks only (a 3 px ring on `section:focus`; amended by METRO-118, it was `[tabindex="-1"]:focus` and drew on a result heading after a tap) and makes `select` inherit the font; the View Transition rules are in `base.css`.
- `theme-boot.js` is rewritten with the same behaviour (arrow function, `const`, optional catch binding). A blocked store removes the attribute, as the handoff's does.
- The command-palette trigger and shortcut hint are not built; the header has an `actions` slot for them. The map region is a slot; no map is drawn. The slice does not show the taka sign yet (its copy says "BDT"), so `Price` is provided and tested only.
- The landing slice is lazy (above), which the handoff did not consider.
- Drag clamps the sheet at `viewport height - 148 px` and ignores the safe-area inset until release, where CSS `data-snap` is exact.
- Tokens live in four files (`tokens.css` for the entry, `tokens-parts.css`, `tokens-map.css`), and `fonts-mono.css` holds the second font face; the handoff had one `tokens.css` and one `fonts.css`. `--sheet-full` is replaced by `--sheet-top` and `--sheet-reserve`. The mark's looping ping is its own file. The ticket mask ink and the theme-card previews are in `tokens-parts.css`.
- Source CSS was reformatted by the repository formatter (expanded rules, lower-case hex); values are unchanged.

## Consequences

- Easier: one set of tokens drives light, dark, forced-colours and reduced-transparency; a slice adds a component file import, not new tooling. The reference slice at 390 and 1280 px in both themes is the visual check the owner makes.
- The Home link goes to `/`, a full page load while there is no router, and the e2e check that the page has one `a[href='/']` must be revisited when the section nav gets a Nearby link. Each `Brand` has its own gradient and mask ids (from `useId`), so two marks on one page do not collide.
- Font files are not JS or CSS, so the byte gate does not count them: a first visit also downloads Hanken Grotesk, 34,704 bytes, on top of the gated 249,338 / 78,021. The gate also does not count the lazy chunks a visit loads right after the entry (slice JS, slice CSS, adapter and core: 36,104 raw bytes in this build).
- The first visit has 662 raw and 1,979 gzip bytes of headroom left. Levers, in order: drop the duplicated `prefers-color-scheme` dark block by having `theme-boot.js` always set `data-theme` (about 2.5 KB raw, a change to System semantics, so it needs a decision), `light-dark()` (Baseline 2024, below the handoff's 2023 floor), unused tokens.
- Cost of the lazy landing slice: the h1 now arrives with a second request. Lab LCP about 400 ms and CLS 0.0004 (limits 2,500 ms and 0.1, Chromium); real-user LCP is Unverified. The pending `<output>` can flash. The slice needs the entry chunk and then its own chunk, so a failed chunk shows the reload region.
- The CLS control in `e2e/web-vitals-lab.e2e.ts` now prepends its block inside the panel, because the fixed shell no longer shifts with a block put in `<body>`.
- Unverified: View Transition behaviour in Firefox and Safari (feature-detected, falls back to an instant switch); `prefers-reduced-transparency` in a real browser (the CSS is tested as text and by DevTools emulation where Chromium supports it). The new journeys passed locally on Chromium, Firefox, WebKit and the mobile Chromium project (`CI=true bun run smoke`); the hosted run is Unverified.
- `theme-boot.js` is not hashed, so it revalidates on each visit (default `Cache-Control`); it is 0.4 KB.

## Alternatives considered

- Tailwind (or any utility framework): rejected, a new build dependency (ask-first) and a rewrite of the handoff's BEM classes, whose screens are the reference.
- CSS-in-JS: rejected, it injects styles at run time, which the enforced CSP forbids without `'unsafe-inline'`, a nonce or hashes per rule.
- CSS Modules (the ticket's earlier fallback): rejected, the handoff is global BEM with global tokens; renaming every class would break the one-to-one comparison with its screens.
- An inline theme script, or a CSP hash for one: rejected, it needs a CSP change; the external file needs none. A `type="module"` script: rejected, it is deferred, so the first paint would flash.
- Keeping the slice in the entry and raising the budget: rejected, the owner forbids raising it (ADR-0020).
- Removing the handoff's dark `prefers-color-scheme` block now: kept as a lever, not taken, because it changes what System means.
- One `components.css`: rejected, 67 KB in every visit.
