# ADR-NNNN: Short decision title

- Status: Proposed | Accepted | Rejected | Deprecated | Superseded by ADR-NNNN
- Date: YYYY-MM-DD
- Ticket and specification: METRO-NN, specification identity and revision

The status vocabulary is MADR 4.0.0's (proposed, accepted, rejected, deprecated, superseded by ADR-NNNN). A short qualifier in parentheses may follow, for example `Accepted (plan only)`. `Superseded by ADR-NNNN` must name an ADR that exists. `scripts/adr.test.ts` checks the header, the status and the section list of every ADR. Delete this paragraph in a real ADR.

## Context

The forces at play: the problem, constraints, and evidence (link to repository files and evidence documents).

## Decision

The decision, stated in full sentences ("We will ...").

## Consequences

What becomes easier, what becomes harder, and what must be revisited (for example on a dependency upgrade).

## Alternatives considered

Each rejected option and the reason it was rejected.

## Confirmation

How compliance with this decision is checked: the test, gate or script that fails when it is violated (name the file). Write `None (policy)` when nothing enforces it. MADR 4.0.0 makes this section optional; this repository requires it so that an unenforced decision is stated as such, not left to hope.
