# ADR-0011: Security headers, report-only CSP and asset caching

- Status: Accepted
- Date: 2026-11-05
- Ticket and specification: METRO-31 (Plane); no separate specification, the ticket acceptance is the contract

## Context

The SPA is served by Workers Static Assets and `/api/*` by the Hono Worker (`run_worker_first: ["/api/*"]`, see [ADR-0002](0002-runtime-topology.md)). Two header mechanisms are needed because they cover different responses.

- Web-verified 2026-11-05 ([Workers static assets: headers](https://developers.cloudflare.com/workers/static-assets/headers/)): a `_headers` file in the asset directory is applied to static asset responses only, never to responses generated by Worker code, even when the URL matches a rule. Syntax is a URL pattern line followed by indented `Name: value` lines; at most 100 rules, 2,000 characters per line; the same header set by two matching rules is joined with a comma; headers in the file override the default `Cache-Control: public, max-age=0, must-revalidate`.
- Context7-verified 2026-11-05 (Hono 4.13.14): `hono/secure-headers` takes `permissionsPolicy` (directive to values), `referrerPolicy`, `xFrameOptions`, `contentSecurityPolicyReportOnly` and `strictTransportSecurity` (`boolean | string`). Its defaults include `Referrer-Policy: no-referrer` and HSTS `max-age=15552000; includeSubDomains`, so both are overridden explicitly.
- Repo-verified: Vite writes content-hashed files under `/assets/` and copies `apps/web/public/_headers` to `apps/web/dist/client/_headers`; `vite preview` runs the real asset handler in workerd, so the smoke suite fetches the real headers.
- The Maps browser key is referrer-restricted, so `Referrer-Policy: no-referrer` would break it.

## Decision

- Static assets: `apps/web/public/_headers` sets, on `/*`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: geolocation=(self)` and a `Content-Security-Policy-Report-Only` limited to `'self'` (plus `data:` images). On `/assets/*` it sets `Cache-Control: public, max-age=31536000, immutable`. HTML (`/`, `/index.html`, SPA deep links) keeps the default revalidating `Cache-Control`.
- API: `secureHeaders` from `hono/secure-headers` on `/api/*` with the same non-CSP values. Defaults that stay on for `/api/*` (Repo-verified in the installed hono 4.13.14 source): `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, `Origin-Agent-Cluster: ?1`, `X-DNS-Prefetch-Control: off`, `X-Download-Options: noopen`, `X-Permitted-Cross-Domain-Policies: none`, `X-XSS-Protection: 0`, and `X-Powered-By` removal; `Cross-Origin-Embedder-Policy` stays off. Note: `Cross-Origin-Resource-Policy: same-origin` makes browsers refuse to load an API response from another origin in no-cors mode (for example an `<img>` or `<script>`); a future cross-origin consumer of the API must relax it (`cross-origin` or `same-site`) or use CORS deliberately. No CSP, because JSON is never rendered.
- Missing assets: `run_worker_first` is `["/api/*", "/assets/*"]` and `GET /assets/*` goes through the Worker's `ASSETS` binding; an `index.html` answer under `/assets/` becomes a 404 envelope. See Consequences.
- CSP stays Report-Only until the first Maps slice lands. That slice must add the Google hosts it actually uses, watch the browser console for violations, and then re-evaluate switching to an enforcing `Content-Security-Policy`. Until then an enforcing policy could silently break Maps loading, and the ticket owner delegated this choice. The policy has no `report-to` endpoint (none exists), so violations show only in the browser console.
- HSTS is not shipped. When the custom domain is live, add `Strict-Transport-Security: max-age=...` without `preload` (and, on the API, drop the `strictTransportSecurity: false` override). Preload is hard to undo and needs the domain connected first. This is a documented follow-up, not part of METRO-31.

## Consequences

- The shared values live in two places (`_headers` and `app.ts`) because Cloudflare applies them to disjoint response sets. Tests assert both; keep them identical.
- Tested at three levels: `bun test` parses the committed `_headers` and calls the API through `app.request`; the Playwright smoke fetches `/`, a deep link, `/api/scaffold/status` and the hashed asset from the built app in workerd and checks for report-only CSP violations in Chromium.
- Unverified until a preview or production deploy: that the deployed Cloudflare edge applies `_headers` the same way as the local workerd emulation, and edge-cache behavior for `/assets/*`.
- A hashed filename must change with its content; anything copied unhashed into `/assets/` would be cached immutably for a year.
- Finding (Repo-verified locally, 2026-11-05): with `run_worker_first` as an array, Cloudflare no longer interprets `Sec-Fetch-Mode: navigate` (Web-verified, SPA routing docs), so `GET /assets/does-not-exist.js` returned `200 text/html` (index.html) carrying the `/assets/*` rule's `immutable`. `_headers` cannot condition on file existence. Fix: route `/assets/*` through the Worker and turn an HTML answer under `/assets/` into a 404 JSON envelope. Cost: every `/assets/*` request now invokes the Worker (billed as Worker requests) instead of the free static path; acceptable at this scale, revisit if traffic grows. `_headers` still applies to the `ASSETS.fetch` response (the hashed asset is `immutable` in the local workerd smoke).
- Unverified until preview: the same missing-asset and `_headers`-through-`ASSETS.fetch` behaviour on the deployed edge; the smoke test `a missing /assets/ file is never served as immutable` covers it locally and should be run against the preview URL.
- Quality gate: `e2e/headers.e2e.ts` runs in the `Build and smoke` job, which `Quality gates` requires (`needs: [checks, build, security]`).
- The CSP console check has a positive control (a deliberate image from another origin must be reported) so the "no violation" assertion cannot pass vacuously; both run on Chromium only.

## Alternatives considered

- Enforcing CSP now: rejected, Maps hosts are unknown and breakage is silent.
- Setting all headers in the Worker for every request (`run_worker_first: true`): rejected, it bills every request (HTML included) as a Worker invocation. Only `/assets/*` is Worker-first, the smallest set that keeps missing files from being cached as immutable.
- Narrowing the `_headers` rule to hash-shaped names: rejected, a missing hash-shaped URL would still get the SPA fallback plus `immutable`.
- `Referrer-Policy: no-referrer` (Hono default): rejected, breaks the referrer-restricted Maps key.
- HSTS with `preload` now: rejected, hard to undo and the custom domain is not connected.
