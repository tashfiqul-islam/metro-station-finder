# ADR-0023: A small hand-written service worker keeps the app shell offline

- Status: Accepted
- Date: 2026-11-09
- Ticket and specification: METRO-106 (Plane); no separate specification, the ticket and its owner decision of 2026-11-08 (add a small service worker rather than drop the claim) are the contract.

## Context

The manifest, the design's offline state and the share image say the app works offline. Station search by name, the SVG line map, fares and the line list are local data and code ([ADR-0018](0018-where-core-runs.md), [ADR-0022](0022-nearby-screen-one-lazy-boundary.md)), so only the files need to be on the device. Until this ticket nothing stored them, and tests forbade the word "offline" in shipped scripts ([METRO-112](../evidence/metro-112.md), [METRO-114](../evidence/metro-114.md)).

Constraints: no new dependency; the first-visit budget has 275 raw bytes of headroom ([ADR-0020](0020-first-visit-budget-and-lazy-features.md)); the CSP is unchanged ([ADR-0011](0011-security-headers.md)); Workers Static Assets serves the files through `run_worker_first` for `/api/*` and `/assets/*`; the position goes to Google only ([ADR-0009](0009-maps-provider-design.md)).

Facts the design rests on, with their sources:

- Context7-verified (Playwright docs): `page.route` and `context.route` do not see requests a service worker handles and are not applied to fetches the worker starts; the docs recommend `serviceWorkers: "block"` for interception tests.
- Web-verified (MDN, Using Service Workers): a successfully installed new worker waits while the old one controls pages; it may call `skipWaiting()` to take over open pages; a rejected install promise means the worker does nothing; `clients.claim()` adopts open pages. MDN, `ServiceWorkerRegistration.update()`: the script fetch bypasses the browser caches if the previous fetch was over 24 hours ago.
- Web-verified (Cloudflare docs): with `not_found_handling = "single-page-application"` a request that matches no asset gets `index.html` with 200; the implicit `Sec-Fetch-Mode: navigate` detection is off once `run_worker_first` is an array of patterns; static assets get `Cache-Control: public, max-age=0, must-revalidate` and an ETag by default.
- Repo-verified: `/_headers` gives `/assets/*` the immutable header and everything the app CSP; `scripts/bundle-budget.ts` fails on a built JS file the Vite manifest does not list.

## Decision

We will ship one classic worker, `/sw.js`, written by hand in `apps/web/src/sw/` with its logic in `worker.ts` (cache, network and clock injected) and built by `scripts/sw-plugin.ts` after the client build.

- Precache. At build the plugin lists `dist/client` (the page as `/`, every hashed file, the public icons, the manifest and `theme-boot.js`; never `.vite/`, `_headers`, `robots.txt`, `licenses.txt`, source maps, `sw.js` itself or `favicon.ico`), fails the build unless every file Vite's manifest names is in that list, and hashes the paths and bytes into a 12 hex digit version. The cache is `metro-shell-<version>`. Install fetches each file (hashed files may come from the HTTP cache, the others with `cache: "reload"`) and requires a plain 200, HTML only for `/`; any failure rejects the install, so the old worker and its cache stay. `favicon.ico` is left out because a script `fetch("/favicon.ico")` failed under Playwright Chromium while every other icon succeeded (cause Unverified); the page also declares `favicon.svg` and `apple-touch-icon.png`.
- Fetch. Only a same-origin GET is touched. `/api/*`, `/sw.js` and every other origin (Google, fonts) get no `respondWith`, so they never enter the worker's logic or any cache. A navigation is network first: an online visit always gets the current page; a network error, a 5xx or no answer within 3 s serves the cached page of this version if there is one. The network answer is never written to the cache, because a newer page stored under older assets could not work offline. Files under `/assets/` and the precached unhashed files are cache first; a miss under `/assets/` is stored only as a plain 200 that is not HTML. A key is a path without its query string and the shell key is the fixed `/`, so a position or a place name in a URL can never be stored.
- Update. A new worker installs into its own cache and then waits. It does not call `skipWaiting` by itself, because a deploy removes the old hashed files from the server, and an open page that lost its cache could not load its next lazy chunk. The page shows the toast "A new version is ready." with Reload and Dismiss, inside the shell's toast region, in a `role="status"` element mounted empty first. Reload sends the single message `skip-waiting` to the registration's waiting worker; the new worker activates, deletes every other `metro-shell-` cache and claims the page, and the page reloads once on `controllerchange` (only after that press, not when the first install claims the page). If the takeover has not happened in 5 s the prompt says so in fixed words. Dismiss leaves the new worker waiting: it takes over when no page uses the old one, which the browser does on the next visit. A shown page also asks for a newer worker whenever it becomes visible while online (`registration.update()`), and the worker is registered with `updateViaCache: "none"`. The registration's waiting worker is told, not the object seen at install: in WebKit the older reference did not deliver the message (Repo-verified, cause Unverified).
- Registration. `startServiceWorker()` in the entry is a few lines: in production builds it waits for load and idle, then imports `register.ts` as a lazy chunk. The first visit downloads and runs none of it; `sw.js` and the precache requests come after load. Registration is skipped while `navigator.onLine` is false. Failures are dropped without a log.
- Served correctly. `/sw.js` is answered worker-first by the same route as `/assets/*` (`apps/api/src/app.ts`, `run_worker_first` gains `"/sw.js"`): a present file passes through with the static-asset default `max-age=0, must-revalidate` (not immutable), JavaScript MIME type and the app CSP; if it were ever missing the SPA fallback's `index.html` becomes a no-store 404 envelope, so a browser never reads HTML as a worker. Scope is `/`, the script's own directory, so no `Service-Worker-Allowed` header is needed. `_headers` and the CSP are unchanged: `script-src 'self'` covers the worker and `connect-src 'self'` its fetches.
- Offline behaviour. Station picker, map, fares and the line list run from the cached files. The place-search notice (`navigator.onLine` false) uses the handoff's sentence. The web-vitals beacon is skipped when `navigator.onLine` is false (the sample is dropped, not queued).
- Claims. The offline sentences exist in two places only: the notice in the Nearby chunk and one sentence of the manifest description ("Stations and fares work offline."). Tests pin both places, and fail without the worker in the build. The share image and the install screenshots are not shipped (see the evidence).
- Kill switch. `METRO_SW_KILL=1 bun run build` writes a `sw.js` with no fetch handler that skips waiting, deletes every `metro-shell-` cache, unregisters itself and reloads open pages. Because browsers check `sw.js` on navigation and the file is never immutable, deploying it removes a bad worker from every device that visits; the next normal build, which registers a worker again, ships after it. A missing or HTML `sw.js` does not remove an installed worker, which is why the file must stay present (the route above makes its absence loud).

## Consequences

- Easier: the shell opens with no network; a deploy reaches online users on their next visit and installed apps on the next time they are shown; a broken worker has a documented way out.
- Harder: every deploy now downloads the shell once more in the background (about 350 KB raw, 100 KB gzip, fonts included) after the first visit and after each update; the ceiling for all files is used to 91 percent raw (the worker adds about 3 KB, the registration chunk 1.9 KB), so the next feature must raise it by decision or fit; `scripts/bundle-budget.ts` knows `sw.js` as the one unlisted file.
- The first-visit set grew by 164 raw and 66 gzip bytes (the entry's start function and the beacon guard); headroom is 275 raw. The gate's `dynamicImports` rule keeps the registration chunk out.
- A page open during a deploy keeps running the old version until Reload or the next visit; the prompt can be dismissed, so a very long-lived tab can stay old. An online navigation is never old.
- Playwright route stubs do not apply to a page a worker controls in every browser: with the worker allowed, WebKit let the real Maps script through during development of the e2e spec (Repo-verified, two runs; see the evidence). The project default is `serviceWorkers: "block"`, and the one spec that allows the worker fails on any request leaving the machine and never asks for a Google request.
- Firefox: `setOffline` fails navigations with `NS_ERROR_OFFLINE` before the worker can answer, so the two real-server tests that use it skip Firefox with a recorded reason; the static-server group covers Firefox by stopping the server.
- Unverified: behaviour on real iOS Safari and Android Chrome installs (storage eviction, update timing), the effect of the background precache on a slow mobile connection, `favicon.ico` fetch failure outside Playwright.
- Revisit on a Vite, Workers Static Assets or `@cloudflare/vite-plugin` upgrade (the plugin reads `dist/client` after `writeBundle`), or when a second screen or route is added (the page cached for navigations is the single screen).

## Alternatives considered

- Workbox or `vite-plugin-pwa`: rejected, a new dependency and a larger worker for a four-strategy cache; the owner asked for a small hand-written one.
- Calling `skipWaiting` on install: rejected, it can strand an open page without the files its next lazy import needs, and it hides a half-applied update.
- Updating the cached page from every network answer ("stale while revalidate"): rejected, the cached page could then name assets the cache lacks.
- Reloading automatically when the new worker takes over: rejected, it can discard what the person typed or picked; the prompt asks first.
- Precaching from the registration page (a list fetched at run time): rejected, the list must be the build's own record, checked against the manifest at build time.
- Serving `/sw.js` through `_headers` rules for `Cache-Control`: not needed, the static default already revalidates, and the owner's rule is to leave `_headers` alone.
- A `Service-Worker-Allowed` header: not needed, the script is at the scope root.

## Confirmation

- `apps/web/src/sw/worker.test.ts`, `register.test.ts`, `start.test.ts`, `sw.test.ts` (Vitest, per-file thresholds): routing (API, Google, other methods and the worker itself untouched), install failure on a 404 or an HTML answer, the cache name, deletion of old versions, network first with the 3 s wait, cache first with query-free keys, the kill switch, the message check, a scope whose `fetch` must be called as a method, the prompt, its focus, the 5 s failure text and no registration offline.
- `scripts/sw-plugin.test.ts` (Bun, 100 percent): the shell list, the manifest cross-check that fails the build, the content version. `scripts/bundle-budget.test.ts`: `sw.js` is listed, never first-visit, counted in the ceiling.
- `apps/api/src/assets-route.test.ts`, `index.test.ts`: `/sw.js` passes through, a missing one is a no-store 404, only GET and HEAD.
- `e2e/offline-shell.e2e.ts` (four browsers): no worker request and no registration chunk before load; offline reload, picker, map, fares, line list, deep link without a stored query; a 200 from `/api/*` never cached or answered offline; update, Reload by keyboard, Dismiss, a removed file still served, an install that fails; no request leaves the machine. `e2e/web-vitals-lab.e2e.ts` runs with the worker allowed. `e2e/station-picker.e2e.ts` pins where the word "offline" may appear in the build. `scripts/brand-assets.test.ts`, `scripts/build-brand-assets.test.ts`: the manifest sentence.
- Mutation checks run for this ADR (restored after): a cache-first route for `/api/*`, registration without the scheduler, no cached page fallback. Each made the named tests fail.
